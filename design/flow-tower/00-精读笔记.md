## 2. 分层/金字塔记忆：已解决得比较好的三件事

| 能力 | 代表 | 具体机制 |
| --- | --- | --- |
| 递归摘要 + 叶层留原文 | RAPTOR、MemTree、GraphRAG、HiRAG | RAPTOR 叶=100-token 连续块 + SBERT，UMAP→GMM 软聚类→BIC 定簇数→摘要→递归；HiRAG 用 GMM 生成 summary entities 作 semantic hub |
| 原文回溯句柄 | ReadAgent、MemGPT、HORMA、ConvMem | `⟨Page N⟩` 页签且原始页**原位替换** gist；MemGPT 外部库分页；HORMA note 带 provenance 指向 timestamped raw trajectory；ConvMem 用 residual buffer 的 semantic skip connection 把未改原文直送末层 |
| 按查询决定"看多深" | APDMem、MemWalker、HORMA | APDMem 四层 L0→L3 + 7 个 action + `Tmax=20`，只下钻 8% haystack；MemWalker 从根 triage、叶信息不足可 action -1 回退；HORMA 用 GRPO 学导航，<1000 tok/query |

**一个反直觉但重要的检索结论**：RAPTOR 在 QASPER 上 **collapsed tree（全层压平 + 2000-token 预算竞争）胜过逐层 top-k 下钻**；Harness the Memory 的 M6 分层树也用 collapsed-tree。固定比例逐层下钻不是默认最优解。

## 3. "流动"的学术原型（这是构思最需要的一节）

### 3.1 最贴近：MemTree（ICLR 2025，在线动态树）
- 节点 `v=[c_v, e_v, p_v, C_v, d_v]`；根是空结构节点。
- 插入：从根比子节点余弦相似度，超过**深度自适应阈值** `θ(d)=θ0·e^(λd)` 则下钻；到叶则 `Expand v into a parent` 并对父做 `Aggregate(c_v, c_new|n)` 重摘要；全不达标则挂新叶。
- 原文核到：`θ0=0.4, λ=0.5`，观测**最大深度 13、平均分叉 2.1**，插入复杂度 `O(log N)`，自称 online hierarchical clustering（OTD）。
- 关键含义：**塔的形状由内容自己长出来，不是预设层数**；`θ0` 从 0.8→0.4→0.1 会让树从 1–2 层变到 8–14 层。
- 缺口：只有"叶展开 + 父重摘要"，**没有遗忘、剪枝、跨树链接**。

### 3.2 其他可流动的零件
| 来源 | 机制（原文术语） | 构建性质 |
| --- | --- | --- |
| HiRAG | 按 `cluster sparsity CS_i` 动态决定层数，`ϵ=5%` | 离线 `indexing is offline` |
| Harness the Memory · M6 | `lazy construction`（首次 read 才建）、`top-level deduplication and temporal decay`、demote 被新条目取代的摘要节点 | 惰性 |
| Harness the Memory · M4 | `evolution-triggered rewrites`，LLM 重写受影响的邻居 | 在线 |
| Harness the Memory · M5 | `rebuilt periodically rather than incrementally, with a cached graph serving queries between rebuilds` | 周期重建 + 缓存 |
| Harness the Memory · M8 | `online skill-evolution pipeline (clustering, summarisation, merging, pruning)` | 在线 |
| HORMA | `F_{t+1}=T_F(F_t,a_t,o_t)`，`Recursive Skill Refinement`，skill library 4 轮长到 63 个 | 在线 |
| MemGPT | 超 70% 发 `memory pressure` 警告，超 100% 驱逐约 50% 并用旧 `recursive summary` + 被逐消息生成新摘要 | 在线换入换出 |
| ReadAgent 附录 I | `merge pages iteratively … and then re-gist the new set of pages`（内容驱动页粒度重排） | 重排 |
| 游戏 Agent 综述 | `new experiences traverse the tree, merging with existing nodes or forming new branches, while recursively updating parent summaries`；`signal-triggered consolidation` | 综述归纳 |

### 3.3 明确是"不流动"的（别抄错）
RAPTOR、MemWalker、ReadAgent、GraphRAG、HiRAG、ConvMem 都是**离线一次性构建或逐查询计算**；APDMem 是"ingestion 固定四层 + 按需物化 L1/L2"，**层数不流动**。游戏 Agent 综述把 `Selective consolidation and forgetting` 明确列为开放挑战。

## 4. 两个 DSH 插件与 CoMeT：可直接复用的骨架

### 4.1 bgx666 版（会话内上下文压缩替换）
- 挂载：`package.json` 的 `dsh.bundle.patch:./cordis.patch.yml`，`cordis.patch.yml` 只 `insert: {id: memory-tree, ...}`，**不禁用 compaction-basic**；`index.js` 靠模块顶层副作用 patch `Base.prototype.summarize` / `compactIfNeeded`，用 `Symbol.for(...)` 防 HMR 重复包裹。
- 真实常量（`index.js:107-110`，已本人复核）：`nodeBudget=1000`、`mergeThreshold=9`、`branch=3`、`maxMerges=8`；另有 `chunkTokens=30000`、`maxChunks=12`、`triggerTokens=500000`、`retainMessages=30`。
  - **坑**：`tests/async.test.js:209` 仍是 `mergeThreshold:8, branch:4`；`index.js:316` 注释与 `README.md:318` 的「8/4」是过时描述。以 `index.js` 为准。
- 上浮 `mergeUp`（`engine.js:389`）：某层活跃节点 ≥9 → 取最早 3 个合并成 `level+1` 父节点，子置 `parent_id` 且 `is_active=0`（append-only，不删除，故仍可下钻）。层级无硬上限，由 `stats.depth` 决定 break；`status.js` 的 `MAX_DEPTH=6` 只是显示上限。
- 存储：`node:sqlite` 单库 `$DSH_HOME/memory-tree/memory_tree.db`，表 `nodes/runs/keeps/session_prefs`，`PRIMARY KEY(session_id,id)`；节点 ID `node{level}_{三位序号}`；原文在 `details`（`{role,content,time?}`），结构化字段在 `meta.fields`；`SCHEMA_VERSION=2`。
- 下钻：`explore_memory_tree` **只接受 `node_id` 一个参数**，无关键词搜索、无直达叶子的捷径；靠 prompt 引导"通常 2~4 次调用、够用就停"；`DETAIL_TOTAL=12000`、每条 `700` 字符、最多 40 条。UI 卡片按需 `/memory-tree/api/node` 拉取，收起即清缓存。
- 防丢失：`NODE_MARKER='[已压缩 · 不需要压缩]'`、渐进前缀分片（先建最长前缀命中 provider cache）、7 类 prompt 分工（leaf / parent / skeleton / budget / retry / leaf_scope / leaf_scope_chunk）、`parseNodeJson` 三级恢复、`mechanicalNode` 兜底、`applyBudget` 有损硬裁、`beginRun/commitRun/rollback` 防孤儿、`toolPairingBalancedBefore/After` 校验。

### 4.2 qinghuaju 版（跨会话磁盘长期记忆，不碰 compaction）
- AST 软决策树：Markdown 解析成带唯一 `path`（`/root/segment`）、`parentPath`、`depth`、`kind`、`hash`、`content` 的节点；软链来自 embedding（`cos≥0.72`、每节点 ≤3 邻居）+ 一跳激活扩散（父 ×0.55、邻居 ×0.55·sim）。
- `hot/warm/cold` 三库，`hotDays=30`、`warmDays=180`、`tierWeights {1, 0.9, 0.78}`；六项打分 `0.55·cos + 0.20·lexical + 0.25·RRF` × tierWeight + `0.06·importance + 0.05·recency + 0.03·usage`；`recalls` 与 append-only `audit` 表。
- `space.mjs` 按 cwd 解析 `project` / `global` 空间，是这批资料里**最接近"多塔"的现成隔离概念**；明确限制：无 consolidation、单 writer、换 embedding 模型向量不可比、>~50k 节点全余弦扫描不可行、多机 CRDT 在路线图 Phase 4。

### 4.3 CoMeT（comet-memory 0.5.0）
`depth 0–2` 树 + T1 短摘要（常驻缓存）/ T2 详细摘要（首次由 SLM 从 raw 惰性生成后缓存）/ T3 完整原文；`add_document` 声明 "Full raw content is stored in the vector store without truncation"。**lossless 是架构声明**：README 未给逐字节一致性校验，benchmark 是 27% token / 9-of-10 accuracy，且 6/10 题需 link traversal。PyPI 元数据：`Development Status :: 3 - Alpha`，无源码仓库链接。

## 6. 最重要的三条反证（会直接决定"分总层"该怎么设计）

1. **跨塔概括层在资料里是空白，且是单点故障**。13 篇论文里没有"塔尖之上对所有会话做语义概括 + 按查询路由到某座塔"的完整实现；26 个开源项目里也没有——最接近的 `PageIndex File System` 是 **Cloud-only、本地源码未核到实现**，`OpenHands Agent Canvas` 是基础设施级路由而非内容概括，`graphiti group_ids` / `MemOS Multi-Cube` / `claude-mem 跨 harness 汇总开关` 只是零件。
   - APDMem 原文自承：`does not explicitly model cross-session relationships`；`retrieval recall depends on the quality of the L0 thematic summaries: if a summary omits a relevant detail, the corresponding turn may receive lower BM25 and dense-retrieval scores`；`systematic summary-quality evaluation … future work`。RAPTOR 约 4% 摘要轻微幻觉。
   - **含义：塔尖层一旦漏掉一个细节，下面整座塔都检索不到。它既是召回瓶颈，又是全局单点。**
2. **召回越多越伤决策**（NeurIPS 2026《Harness the Memory》，作者自建受控 harness，11 substrates / 3 骨干 / 4 基准 / 26 指标，非第三方复现）：原文 `retrieving more entries helps QA but hurts agentic decisions, and an attention probe … attention shifts away from the task context toward the retrieved`；ALFWorld `k=1→5` 掉约 7 点；`no single substrate can simultaneously serve recall … action selection … graceful scaling`；`a substrate optimal for short sessions can thus become a liability`；`finer query-level routing remains largely open`。
   - **含义：分总层若只是"更大的摘要 + 更宽的召回"，会在序列决策任务上帮倒忙。它应该更像路由器 + 预算控制器。**
3. **动态重组与缓存/延迟直接冲突**：M5 周期重建 + 缓存图、M6 首次 read 才构建、M8 每次 read 重新 prefill（262K 时 1s→**98s**，仅 flat <10s）；APDMem 提到 `cold-start latency` 并用 L1/L2 缓存缓解；PageIndex `utils.py` 是这批里**唯一**显式处理 `prompt_cache_key` / `_billed_cache_writes` / `_cache_off` 的实现。
   - **含义："流动"意味着塔形频繁变化，而塔形变化会让前缀缓存失效。这是流动塔最主要的工程代价。**
