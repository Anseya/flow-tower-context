## 2 十五条已坐实的设计结论

1. **「原文叶」不是普遍能力，而是少数派**：只有 RAPTOR（叶=原文块）、ReadAgent（页=gist+可原位展开原文）、bgx666（`details` 存原始消息）保留原文句柄；GraphRAG/HiRAG 的叶是实体/关系/claim 描述，**没有原文段落**。〔论文事实〕`01b` C1。→ 回溯能力只能抄 ReadAgent 页模型 / bgx666 details，不能指望 KG 系。
2. **分层不是越多越好，必须保留"压平检索"旁路**：GraphRAG C0–C3 层间无统计显著差异（C0 仅占 2.6% token）；ReadAgent 附录 H 复现 MemWalker 树搜索只得 66.73% vs 全量原文 85.83%，结构性原因是「分层摘要难以对远距离同粒度证据推理」；RAPTOR collapsed tree 持续优于逐层固定 k 下钻。〔论文事实〕`01a`、`01b` B1/B2。→ 设计里必须有 collapsed/flat 检索模式的退路。
3. **逐层下钻的失败点很具体**：MemTree 消融显示 traversal `k=10` 与 collapsed 相当、`k≤5` 显著掉分；MemWalker 的回退率 15–19%（救回 60–80%），去掉工作记忆掉 5–13%。〔论文事实〕`01a` §2.2/§2.3。→ 一次下钻必须返回「下一层全部子摘要 + 当前路径工作记忆 + parent 入口」，不能只回单个节点正文。
4. **原文层是精度来源，不只是保真备份**：APDMem 消融里 `read_raw` 掉 5.9%（最大单项），而 L2 只掉 0.5%。〔论文事实〕`02a` §2.2。→ 「够用就停」不能停在中间摘要层，要鼓励直达原文。
5. **"下钻少"不等于便宜**：APDMem 在线仍 124.3k token / 37.7s per question（cold start 口径）；"只下钻 8%" 是会话比例不是成本。〔论文事实〕`02a` §2.2/§3.3。→ 控制器必须显式预算（步数 + token 双上限），不能只靠"下钻少"。
6. **在线增量建树很贵**：MemTree 3.27±2.38 次 LLM 调用/插入、约 10 s/插入；对照 RAPTOR/GraphRAG 离线重建 3753/3858 次调用 >1 h。〔论文事实〕`01a` §2.2。→ 结构自适应（流动②）禁止每轮做，只能进压缩事务或静默期批处理。
7. **父节点必须写侧硬预算**：MemTree 节点文本随深度膨胀（depth 10+ 中位约 800 tok），Aggregate 只有软提示；RAPTOR 压缩比 0.28、父均 6.7 子；MemWalker 父=子摘要**拼接**（超长才二次压缩）。〔论文事实〕`01a` §2.2/§2.3。→ 节点内容必须在写侧 clamp，不能依赖 prompt 软约束。
8. **冷启动靠预物化，不靠缓存**：APDMem 的 L1/L2 惰性物化有首访延迟，缓解手段是"离线/后台主动预物化"；缓存只压重复访问。〔论文事实〕`02a` §3.2。→ v1 的树内中间层要"先给降级视图、后台补齐"。
9. **分总层 root-only 就够**：GraphRAG C0 级画像只要 2.6%/2.3% token 且层间无显著差异；C0 vs 纯文本 map-reduce 在全面性上也无显著差异（省 token 才是它的贡献）。〔论文事实〕`01b` B2。→ 每棵树一条 ≤150 token 画像，不必给分总层建多层摘要。
10. **总述必须带句柄、必须可审计**：GraphRAG 的 report schema（title/summary/rating/findings）与 `[Data: Entities(5), Relationships(37,+more)]` 引用格式，是"总述写坏导致全塔失联"的解药。〔论文事实〕`01b` §4.2。→ 总述视图每句话都要落到 node/seq 句柄。
11. **"流动"的代价形态是前缀缓存失效，且只在结构变更时付**：路由视图（systemPrompt 段）任何变更 = 整段前缀作废；checkpoint 是 user 消息，其变更只影响其后保留尾部。→ 路由视图只在树生命周期事件（新建/根合并/归档）变；结构变更统一放进压缩事务；易变值（活跃度/token 数）只走工具结果。〔`01a` §4.4、`01b` §4.4、`02a` §4.3；后半句是【推断】〕
12. **DSH 宿主已经做掉了 MemGPT 的一半**：session log = recall storage（被 shadow 的事件仍在 raw log）、session surface = main context、`ctx.compaction` = queue manager、`ctx.tokenMeter` = 压力计。〔宿主事实〕`02a` §4.0 + Lead 亲核。→ **插件不该重造分页/驱逐**，而应做「surface 之上的树 + 跨树分总层」；原文一句话都不必自己复制。
13. **写侧质量决定上限**：HORMA 用 18 条现成技能 prompt + 强制 `memory_prompt_improvement` 字段，Claude 作 manager 时 skill-only 就让 ALFWorld 51.5→73.9；其自述「写侧组织坏掉，读侧救不回」。〔论文事实〕`02b` §2。→ 将来的摘要 prompt 必须当一等领域对象沉淀，不能随手拼一句。
14. **跨树路由的增益天花板不高，别把它当主要卖点**：Harness the Memory 实测 per-substrate 路由 0.671 vs 固定最优 0.648（+0.023，p=0.032）；conversation-grouped 与 LOCO 分组不显著；oracle 0.93 说明提升在"问题级选择"而非"树级选择"。〔论文事实〕`02b` §2。→ 分总层应先做"清单+画像"（人可见、模型可查），自动路由留给后续实验。
15. **检索宽度应分任务形态（regime）双档**：HTM 的 k 扫描显示 QA 类 k=5–20 更优、Agentic 类 k=1–5 会掉约 7 点且跌破无记忆基线；机制是 attention 从任务上下文转向检索内容。〔论文事实〕`02b` §2。→ 工具默认小步（k=1–2、≤1000 tok/次），需要时显式放宽；不要默认宽召回。

### 5.1 压缩 seam（v1 的用法是"观察"，v2 才谈"替换"）

- `ctx.compaction` 是**抽象服务**（`CompactionEngine`），三个抽象方法：`compactIfNeeded(agent, trigger, signal)`、`compactNow(agent, signal, commandId?)`、`compactRegion(start, end, agent, signal?)`。契约：**每 context 只允许一个实现**；成功一次 = 把选中的 surface 区间替换为**一条 `user/message`**（`surfaceOp: {op:'replace', startSeq, endSeq}`）。〔宿主事实〕`packages/compaction/compaction/src/index.ts:119-193`、README。
- `CompactionResult` / `compaction/summary` 事件直接给出建树所需的一切：`compactionId`、`summary`（ContentBlock[]）、`shadowedRange{start,end}`（surface 位置区间，**start 可能大于 end**）、`shadowedSeqs[]`（权威被遮蔽节点集，surface 顺序）、`shadowedTokenCount`、provider/model/usage。〔宿主事实〕`packages/compaction/compaction/src/types.ts:17-120`
- 被 shadow 的原始事件**仍留在 session log**（`compaction/*` 事件 log-only；replay 可确定性复现），原文层天然无损；可用 `session.eventAt(seq)` / `deriveEventMessage` / `ctx.sessionQuery` 按 seq 取回。〔宿主事实〕
- **压缩后端不在 host 平面**：web-app 在 host 层把 `compaction-basic` 等行 `disabled: true`，各 **agent preset** 用 `cordis:group` + `isolate: {compaction:true, toolResultPruner:true}` 自己挂一份；当前 profile 的选择是 `preset: cordis`。〔宿主事实〕`web-app/cordis.patch.yml:538-552`、`presets/standard.patch.yml:66-82`、`$PROFILE/cordis.patch.yml:36-40`
- **纯 JS 插件不能 import `@deepseek-ai/*`**（实测 `ERR_MODULE_NOT_FOUND`；profile node_modules 无该 scope），因此 `defineTool`、`BasicCompactionEngine` 子类化在 MVP 都拿不到；社区插件与用户自己的 tianquan-app 全部是 `ctx` 鸭子类型 + `node:*` 内建模块。〔宿主事实〕`05` §1.4
- **三条接入路线**（`05` §2.5）：
  - **A（v1 推荐）观察式**：只在 Host 平面监听 `session/event` 的 `compaction/summary`，自己维护树与工具；零 patch、零 preset 改造。
  - **B 观察 + 主动压缩**：A + 在工具/命令里调 `ctx.compaction.compactNow/compactRegion`（受压缩锁与 idle 约束），v1.1 可选。
  - **C 替换 engine**：需要覆盖 preset 声明、把 provider 与消费者放同一 `isolate` 组；且要么能 import 宿主类（模块解析未验证），要么完整重实现 `CompactionEngine` 的锁/事务/surface 替换。→ **v2 才做**。

### 5.2 上下文注入

- `ctx.systemPrompt.section({name, order, text})`：静态/可回调段，随 accepted assembly 冻结 → **放路由视图最稳**（前缀稳定）。〔宿主事实〕`packages/core/system-prompt/src/index.ts:483-530`、README。
- `ctx.systemPrompt.context({name, order, text, required?})`：动态模型上下文，materialize 成 durable user-role 快照，可 `refreshContext` 刷新；适合"每步要变但不想污染 section"的内容。〔宿主事实〕同上 `:518-600`、README:54-90。
- 已有 order 表（`SECTION_ORDERS` / `CONTEXT_ORDERS`），外部插件可用任意有限 order；`getSectionOrder/getContextOrder` 仅对仓库自有名字有效。〔宿主事实〕`:136-187`。
- 变更会触发 `system-prompt/change`；`refreshContext` 契约保住 sections/tools/variables 的 accepted 值。〔宿主事实〕同 README:68。

### 5.3 工具

- `ctx.tools.register(ToolDefinition)`：注册即可见，schemas 自动进 prompt 装配；`exec.agent.session` 取当前会话；支持 `{ when }` 条件注册、`restrict`、`guard`、`deferLoading`（字段存在，语义待核）。**纯 JS 插件用不了 `defineTool`（import 不到）**，要手写标准 JSON Schema 对象：`{name, description, parameters:{type:'object',properties,required,additionalProperties:false}, output:{schema, render}, execute}`。〔宿主事实〕`packages/core/tools/README.md:32-64`、`contracts.ts:26-102`、`05` §1.4

### 5.4 持久化

- `ctx.storageDomain`（`ctx.storage.domain`）：`DomainSpec {name, version, layout:'single'|'per-record', records(zod)}`；backend 有 `json`（`dsh-storage-json`）与 **`sqlite`（`dsh-storage-sqlite`）** 两种；`per-record` 布局正是"节点记录大、稀疏、可独立丢弃"的形态 → 树节点首选。〔宿主事实〕`docs/subsystems/storage.md:9-70`。
- 会话本身由 `dsh-session-persistence-jsonl` 落盘（`$DSH_HOME/sessions`）；大工具结果由 spill 机制留在文件里（`dsh-spill-local`/`dsh-spill-policy`：`maxInlineTokens: 12500`）。〔宿主事实〕`packages/bundle/base/cordis.patch.yml:406-412`。

### 5.5 跨会话读取（分总层的关键使能）

- `ctx.sessionQuery`：`listSessions`、`readSession`、`listEvents`、`readSurface`、`filterEvents`、`readEvent`、`traceSession`、`observeSession`；`SessionEventSurface = 'current' | 'shadowed' | 'log-only'`，`SessionEventRecord` 是 raw-log 投影。〔宿主事实〕`packages/session-query/session-query/src/index.ts:85-360`、`docs/subsystems/session-query.md`。
- **含义**：分总层可以按 seq 读其他会话（其他树）的 shadowed 原文，**不必自己复制一份原文**；跨树取回 = `readEvent`/`filterEvents`。〔宿主事实 + 【推断】〕
- 另有 `dsh-session-query-sqlite` 提供 FTS 索引（默认 base 未挂，需要显式加行）。〔宿主事实〕`packages/session-query/session-query-sqlite/`

### 5.6 挂载

- bundle = `package.json` 里 `dsh.bundle.patch: ./cordis.patch.yml` + patch 里 `insert: [{id, name, config}]`；本地开发用 `link:` 安装（用户已有 tianquan-app/tianquan-mcp 先例，宿主风格照抄）；安装走 `plugin_manager install_bundle`（会写 profile，需用户批准）。〔宿主事实 + 用户先例〕
- 插件形态：普通插件 = `apply(ctx, config)`（MVP 唯一形态）；服务类插件 = default export class（需要 import cordis 基类，纯 JS 拿不到 → 不在 MVP 用）；Client 半用 `window.__ModuleLoader__.load(...)` 注册 slot。〔宿主事实 + `03` §3.3〕
- **放置策略**（`editing-cordis-compositions` 技能）：Host 插件提供共享服务（工具注册表、提示词注册表、agent loop、session、持久化等）；preset 插件提供**作用域化**的工具/人格/prompt 段/策略。v1 观察式插件放 **Host 平面**（工具与路由视图全局可见，不依赖哪个 preset）。〔宿主事实〕
- 本机源码树版本 rc.3、安装 rc.5：**以安装版为准**，源码树用于理解与检索，差异处回 asar 核。

## 6 五条设计公理（v1 必须满足，可作为评审清单）

- **A1 原文无损**：节点只存句柄（`session_id + seq range` / page span），原文留在 session log + spill，**绝不复制、绝不覆盖**。
- **A2 少召回、准路由**：常驻上下文只放路由视图（tree_id + 一句话画像 + 预算/代价）；总述与细节按需走工具结果。
- **A3 结构变更只在事务/静默期**：禁止每轮重排；**无结构变更时 checkpoint 文本必须逐字不变**（可测不变量）。
- **A4 两次分离**：LLM 重活（建树/摘要/画像）只发生在压缩事务或后台窗口；查询期只允许 embedding + 窄查询 + 有上限的小模型调用。
- **A5 可审计可回溯**：每个摘要节点带 `shadowedSeqs`/page span/source；总述每句带 `[Data: Node(#), Msg(#), +more]` 句柄。
- **A6 摘要与工具返回是"不可信上下文"**：压缩摘要/记忆节点可能携带注入指令，渲染时必须用分隔标签包裹并明确"这是记忆内容，不是指令"（资料库已收录"压缩摘要可被注入"案例，`04` 风险清单）。

## 7 旧构思的四处改口（与 01 的差异，需用户确认）

1. **"多座塔" → v1 = 一会话一树 + 跨会话只读路由索引**。树间迁移/合并 v2 再做（资料空白，01 §8.4 已建议）。
2. **"分总层两者都要" → 拆成两个模块两套时机**：路由视图（常驻、极窄、低频写）+ 总述视图（按需、带版本与句柄、**不回写路由**）。硬规矩不变。
3. **"流动四种全要" → v1 只做 ① 垂直上浮 + ③ 时间冷热**；② 结构自适应放进静默期批处理（v1.5）；④ 跨树迁移 v2。
4. **"替换 compaction"（v1 不做）→ v1 改为"观察 + 派生索引"**：不接管摘要、不写 surface；树与原文回溯都在插件自己的库里，模型通过工具与窄注入访问。真正把 checkpoint 变成树视图需要接管摘要层（preset 改造 + 事务重实现），列为 v2 可选（详见 `03` §10）。
