# 流动塔 · 词典式访问层（对用户「像查字典那样」的评估与重构建议）

> 日期：2026-11-15
> 输入：用户新思路「像查字典那样」。本文件评估该思路、给出**重构后的 v1 设计**，并列出对 `03-实现方案-v1.md` 的改动清单。
> 依据：`02-读后综合.md`（15 条坐实结论）、`reading/01a-05`（七份精读）、`05` 宿主事实。
> 状态：**评估稿**。未改代码、未安装插件。

## 0 我的判断（结论先行）

**「查字典」是对的，而且它修掉了 03 方案里最弱的一环。**

03 的访问路径本质是「树内逐层下钻 + 不透明 node_id」，即 traversal。而本轮精读的硬结论反复指向相反方向：

1. **RAPTOR**：collapsed（全层压平检索）持续优于逐层下钻；**MemTree** 消融显示 traversal 在 k≤5 时显著掉分；**ReadAgent** 附录 H 用 MemWalker 式树搜索只得 66.73%，而"gist 列表 + 页句柄"得 86.88%。
2. **ReadAgent** 的交互是"看到页号 → 直接展开该页原文"；**claude-mem** 是 search（50-100 tok）→ timeline → get 全文；**HORMA** 是 `ls/grep/cd/cat`。这些成功交互都不是"走树"，而是"定位词条 → 看释义 → 取例证"。
3. 观察式接入下，宿主压缩总是从头部切到保留尾巴，**树会退化成单链阶梯**（每次压缩吞掉上一根）：深度 = 压缩次数，找旧细节要跳 N 层。词典是 O(1) 直达。
4. 模型天然会用词典：**词条 → 释义 → 例证 → 参见** 是极低解析成本的交互；而"理解一棵自定义树的层级语义"需要额外 prompt 教育。
5. **精确查词天然是窄召回**，正好对上《Harness the Memory》的"宽召回帮 QA、伤 agentic 决策"。

所以推荐的重构不是推翻，而是**换接口**：**树保留为"编纂结构与证据来源"，对外访问面改成词典**。

> 一句话：塔 = 卷（Volume），记忆单元 = 词条（Entry），分层摘要 = 释义层级，原文 = 例证/引文（Citation→seq），跨树链接 = 参见（see also），流动 = 词条修订与义项演替。

## 1 证据映射（为什么这不是拍脑袋）

| 研究结论（出处见 `02`） | 词典对应 |
| --- | --- |
| RAPTOR collapsed > traversal；MemTree k≤5 掉分 | **压平词头索引** > 树遍历 |
| ReadAgent：页句柄原位展开、模型自主决定读几页 | **词条 + 引文号直达原文** |
| claude-mem：search(~50-100 tok) → timeline → get | **查词 → 看释义 → 取例证** |
| HORMA：`ls/grep/cd/cat`，note 引 raw 轮次 | **目录浏览 + 词条定位 + 引文** |
| aider repo map / PageIndex / Serena：索引只导航，原文不动 | **词条只存引用，原文留 session log** |
| APDMem 消融：`read_raw` 是精度主力（−5.9%） | 每条释义必须能一键到例证 |
| HTM：宽召回伤 agentic 决策 | 词典命中 = 窄召回 |
| HORMA：写侧组织质量决定上限 | **词典编纂质量 = 写侧质量**（真正的成本项） |
| GraphRAG：社区报告 schema + `[Data: ...]` 引用 | 词条结构 + 引文标注 |
| RAPTOR/MemTree 的祖先-后代重复 bug | 一词条多义项 + 引文去重（同一事实只入一条） |

## 2 词典模型定义

```
卷 Volume        = 一棵"塔"（v1 = 一个会话；scope 可 project/global）
词条 Entry       = 一个可被查的单元（一个概念/文件/决定/错误…）
  词头 headword  = 规范键（唯一、可规范化、可别名重定向）
  义项 Sense[]   = 该词条的不同含义/阶段（append-only）
  释义 gloss     = 一句话（≤40 tok）
  参见 related[] = 相关词条 ID（see also）
  引文 Citation[]= {seq_start, seq_end} → session log 原文（唯一真源）
  修订 revision  = 同一词条的历史版本链（OED 式：旧义项不删，标 superseded）
词条种类 kind   = file / command / error / decision / task / api-symbol / topic
联合目录        = 卷清单 + 跨卷词头检索（"分总层"）
凡例            = 一次性使用说明（系统提示词稳定段）
缩略目录        = 常驻上下文的词头表（只列词头，不带完整释义）
```

关键点：

- **词条是"可检索的语义索引"，不是对话摘要的替代**。原文一行都不搬（A1 公理不变）。
- **"流动"获得新含义**：增补新词条 / 已有词条加义项 / 义项演替（修订）/ 冷热分层。比"树重排"更轻、更可缓存（词头排序稳定）。
- **多座塔 = 多卷**；分总层 = **联合目录**，按词头跨卷直查，而不是"看塔的画像猜哪座塔相关"（后者增益天花板只有 +0.023，见 `02` 结论 14）。

## 3 v1 数据模型（替换 03 §3）

> 仍是 `node:sqlite` 单库；表替换为 vocabulary 结构。

```sql
volumes(
  volume_id TEXT PRIMARY KEY,      -- v1 = session_id
  scope TEXT,                      -- project:<workspace> | global
  title TEXT, profile TEXT,
  entry_count INTEGER, version INTEGER,   -- 编译版本，注入刷新依据
  created_at INTEGER, updated_at INTEGER
)

entries(
  entry_id TEXT PRIMARY KEY,
  volume_id TEXT NOT NULL,
  kind TEXT NOT NULL,              -- file|command|error|decision|task|api-symbol|topic
  headword TEXT NOT NULL,          -- 展示用
  headword_norm TEXT NOT NULL,     -- 规范化键（小写/路径统一/去空白）
  aliases TEXT,                    -- JSON [string]
  gloss TEXT,                      -- ≤40 token
  senses TEXT,                     -- JSON [{text, cite_ids:[...], superseded_by?}]
  related TEXT,                    -- JSON [entry_id]
  tier TEXT,                       -- hot|warm|cold
  revision_of TEXT, superseded_by TEXT,   -- 修订链（append-only）
  created_at INTEGER, updated_at INTEGER,
  UNIQUE(volume_id, headword_norm)
)
CREATE INDEX ix_entries_lookup ON entries(volume_id, kind, headword_norm);
CREATE INDEX ix_entries_prefix ON entries(volume_id, headword_norm);

citations(
  cite_id TEXT PRIMARY KEY,        -- 如 c1 / c2，词条内编号
  entry_id TEXT NOT NULL,
  session_id TEXT NOT NULL,        -- 跨卷时读原文用
  seq_start INTEGER, seq_end INTEGER,
  excerpt TEXT,                    -- 可选 ≤200 字符摘要片段（仅帮助模型判断，不替代原文）
  created_at INTEGER
)

compile_runs(                       -- 编纂事务/自愈
  run_id TEXT PRIMARY KEY, volume_id TEXT, compaction_id TEXT,
  delta_hash TEXT, committed INTEGER, created_at INTEGER
)
index_meta(volume_id TEXT PRIMARY KEY, injected_version INTEGER)
```

不变量：

- **D1 词条只引用，不存原文**：`citations` 只有 seq 区间与可选短摘录。
- **D2 同词头唯一**：`(volume_id, headword_norm)` UNIQUE；同义概念走 `aliases` 合并，不新建重复词条。
- **D3 义项/修订 append-only**：旧义项不删，标 `superseded_by`（OED 式历史义项）。
- **D4 词条上限**：每卷 ≤ `maxEntries`（默认 200），超出按 tier + 最近引文降级/合并，防止目录爆量。
- **D5 编译幂等**：`(compaction_id, delta_hash)` 只编一次；崩溃回滚未 commit 的 run。
- **D6 注入稳定**：卷 version 不变 → 缩略目录逐字相同；词头按 `headword_norm` 字典序，禁止按热度重排（热度只影响"热词条提示"这一受限字段）。

## 4 词典编纂（写侧）——这是真正的成本项

```
触发：compaction/summary 事件（宿主压缩完成）
  → 取 delta：shadowedSeqs 中尚未被任何 citation 覆盖的 seq 区间（原文仍在 session log）
  → 分块（按 token，遇 tool 配对边界不切）
  → 抽取（v1 确定性 / v1.1 加 LLM）
      确定性：文件路径、命令、错误串/码、标识符、日期、明确决定句（"我们决定…"、"采用…"）
      v1.1 LLM：主题/决定/任务 词条（JSON：kind/headword/gloss/sense/related/cite ranges）
  → 归并：规范化词头 → 命中已有词条则加义项/加引文/更新释义（revision）
                          → 未命中则建新词条
  → 落库：BEGIN IMMEDIATE + compile_run 事务；成功后 volumes.version+1
  → 失败：只记日志，不影响会话；缺词时 lookup 返回"未收录"并建议 browse
```

- **成本**：确定性抽取≈0 LLM；LLM 主题抽取 ≈ 每次压缩 1 次小调用（输出目标 ≤500 tok）。这是把"建树成本"换成"编纂成本"，且可批处理、可开关。
- **质量（HORMA 教训）**：先做**确定性高频类**（文件/命令/错误/API/决定）——这类词条精确、可直接验证；主题类后补。
- **降级**：编译延迟不阻塞会话；`lookup` 未命中时退化为"原文 seq 检索"（在未编译区间做子串匹配，返回片段句柄）。

## 5 访问面（工具重构，替换 03 §6）

| 工具 | 语义 | 参数 | 返回 |
| --- | --- | --- | --- |
| `dict_browse` | 目录页（不知道词时用） | `{kind?, prefix?, volume?, limit?}` | 词头列表（按 kind 分组、字典序）+ 卷清单 |
| `dict_lookup` | 查词条 | `{term, volume?}` | 释义、义项、参见、引文 `[c1 seq 120-141]` |
| `dict_cite` | 取例证原文 | `{cite_id}` 或 `{term, cite_id}` | 该 citation 的 seq 区间原文（逐字） |

共 3 个（可加 `dict_status` 诊断，默认不注册）。设计目标：**一次查词典型 ≤2 次工具调用直达原文**（对比树方案的 2–4 次且精度更低）。

输出用固定"词典排版"（词头 / 释义 / 义项 / 参见 / 引文），模型解析成本低；引文必须带 seq 句柄，可被 `dict_cite` 直接消费。

## 6 常驻注入（替换 03 §5.4/5.5）

两级、都在"卷版本不变时逐字稳定"：

1. **凡例**（`systemPrompt.section`，稳定长驻，≤150 tok）：只讲"你有词典、怎么查、未收录怎么办"，一次性。
2. **缩略目录**（`systemPrompt.context`，≤400 tok，卷集合/版本变化才刷新）：
   ```
   [上下文词典 v7 | 本会话 42 词条 | 另有 2 卷(项目/全局)]
   文件(9): src/hosts.ts, src/tools.ts, …
   决定(6): 采用观察式接入; 不做替换压缩; …
   错误(3): EMFILE; ERR_MODULE_NOT_FOUND; …
   主题(24): 前缀缓存, 流式前缀, 树深, 词典编纂, …
   用 dict_lookup(词) 查释义；dict_cite(句柄) 取原文。
   ```
   只列词头（不带释义）→ token 极省；命中后由 `dict_lookup` 展开。
3. **分总层 = 联合目录**：`dict_lookup` 默认跨卷（按词头精确匹配），返回命中卷 + 词条；注入只在**卷集合变化**时更新（新建/归档会话），不按活跃度刷新。

## 7 「不知道查什么词」的三层兜底（词典式方案的最大缺口）

词典的前提是"知道词"。对话记忆经常不知道词，因此必须有：

1. **browse**：按 `kind`（文件/决定/错误/主题…）或词头前缀浏览——相当于字典的"分类索引/部首检字"。
2. **related（参见/同义词）**：`dict_lookup` 返回相关词条；v1.1 可用 embedding 或 LLM 生成近义词。
3. **timeline（时序视图，v1.1）**：按 seq 时间线分页浏览"本会话发生过什么"——这是"流水账"兜底，保证词典漏词时不失忆。

## 9 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| K1 | **词条粒度**：太细爆量、太粗查不到 | 每卷上限 200；确定性类先做；粒度校验用"同一事实不得两词条"测试 |
| K2 | **编纂成本**：LLM 抽取每轮一调 | 确定性优先；LLM 批量、可开关；目标输出 ≤500 tok；增量（只编 delta） |
| K3 | **同义/多义** | 规范化 + aliases 重定向；一词多义走义项而非重复词条 |
| K4 | **目录刷新破坏前缀缓存** | 只在编译提交后 version+1；注入稳定排序；别按热度重排 |
| K5 | **不知道词** | browse / related / timeline 三层兜底（§7） |
| K6 | **未收录** | lookup 明确返回"未收录"+ 在未编译区间做子串检索兜底，不伪造 |
| K7 | **与"流动树"叙事冲突** | 对外仍叫"流动塔/超级上下文"，内部卷/词条；树作为编纂结构保留在文档里，不暴露给模型 |
| K8 | **多卷重复词条**（同一概念在两卷） | v1 允许各卷独立（隔离清晰）；v1.1 做"跨卷同词条合并视图"（联合目录里标注"另见卷X"） |

## 10 验收（可测）

1. **直达率**：构造 20 个"会话内事实"问题，`dict_lookup` 命中率、平均工具调用次数（目标 ≤2）、`dict_cite` 原文与 session log 逐字一致。
2. **常驻成本**：缩略目录 ≤400 tok；卷版本不变时逐字稳定（哈希比较）。
3. **编纂成本**：每压缩轮新增 token（确定性≈0；LLM 主题 ≤1 次/轮）；单次编译耗时 p50/p95。
4. **兜底**：随机/模糊 query 必须能走 browse 且不空转；未收录时明确"未收录"并给最近似词头。
5. **重复抑制**：同一事实（同一 seq 区间）不得在两条词目里重复出现。
