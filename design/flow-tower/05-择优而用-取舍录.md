# 流动塔 · 择优而用（取舍录）

> 日期：2026-11-15
> 用户要求：**论文与项目不要无脑融合，择优而用、不良则弃，整体遵循奥卡姆剃刀；目标形态是「字典式」。**
> 本文件回答三件事：① 我们用什么标准筛；② 13 篇论文 + 26 个项目逐项裁决；③ 融合后的 v1 **最小充分集**长什么样，以及**明确不做**的东西。

## 0 一句话答案

**融合发生在"零件层"，不发生在"项目层"。**
我们不"接入"任何一个论文或项目；我们只从它们身上**取零件**，按字典主路径重装成 4 个部件。凡是与主路径无关、与宿主已有能力重复、成本不可控、或已被独立反证的东西——**整条扔掉，而不是先放着以后用**。

最终：**13 篇论文 → 只留 5 条结论进设计；26 个项目 → 只留 6 个零件；宿主 DSH 已有的能力全部不重造。v1 = 4 个部件 + 3 个工具 + 4 张表 + 0 新增依赖 + 0 每轮额外 LLM 调用。**

## 1 筛选标准（三把刀，先定再砍）

### 1.1 主路径过滤（字典式）

每引入一个机制，必须回答"它服务 `查词 → 释义 → 例证` 的哪一步"：

| 主路径步骤 | 允许的机制 | 不允许的机制 |
| --- | --- | --- |
| 建词条（写侧） | 词头抽取、规范化、义项归并、引文定位 | 建树、建图、重排、训练 |
| 查词条（查侧） | 词头索引、前缀/分类浏览、别名重定向 | 逐层导航、多轮控制器、宽召回 |
| 取例证（证据） | seq 区间直达、原文回放 | 有损压缩、改写原文、另存副本 |

回答不了的问题，一律不进 v1。

### 1.2 证据等级过滤

- **只采信机制与反证**：论文的 benchmark 数字一律当"作者自报"，不作选型依据（本轮已发现多处口径互相矛盾）。
- **有独立反证者淘汰**：例如"分层越多越好"（GraphRAG C0–C3 无显著差异 + ReadAgent 附录 H 反证树搜索）→ 分层只留"释义/义项"一层语义，不做多层树。
- **没有可测收益者淘汰**：跨树路由实测增益仅 +0.023（Harness the Memory）→ 联合目录用**精确词头匹配**（可测），不做"画像猜树"。

### 1.3 成本过滤（奥卡姆量化）

| 成本类型 | 接受上限（v1） |
| --- | --- |
| 新增外部依赖 | **0 个**（不用图库/向量库/Chroma/服务进程） |
| 每轮额外 LLM 调用 | **0 次**（v1 确定性编纂；主题抽取推迟 v1.1） |
| 新增常驻 token | ≤ 400（缩略目录）+ ≤150（凡例） |
| 新增表 | ≤ 5 张 |
| 新增工具 | ≤ 3 个 |
| 与宿主重复 | **0 处**（session log / compaction / tokenMeter 已有的一律不重造） |

**判据口诀**：能删就删；能放进 v1.1 就推；能靠宿主就不写；写了要能测。

## 2 论文裁决（13 篇 → 5 条结论进设计）

> 图例：**采** = 进 v1 设计；**改** = 改造后进；**参** = 只作预算/参数参考；**戒** = 只作反证/风险声明；**弃** = 整篇不用。

| # | 论文 | 裁决 | 我们取什么 | 我们扔什么（为什么） |
| --- | --- | --- | --- | --- |
| 1 | RAPTOR | **采 + 参** | ① `collapsed`（压平索引）优先于逐层下钻——这正是词典查词；② 压缩比 0.28、父均 6.7 子作预算参考 | GMM/UMAP/BIC 聚类、离线递归建树（我们不需要聚类；离线重建成本高且与词典语义无关） |
| 2 | MemTree | **改** | ① 节点内容必须**写侧硬 clamp**（它的问题：节点随深度膨胀到 ~800 tok）；② 祖先-后代重复要按子树去重 | 在线逐层插入、`θ(d)` 自适应阈值、每次插入 3.27 次 LLM 的沿路径重写（贵、只服务树形，不服务词典） |
| 3 | MemWalker | **改** | 一次查询返回「候选列表 + 工作记忆 + 回退入口」的交互契约 → 改造为 lookup 的「义项 + 参见 + 上一卷/词条」 | 逐层 LLM 导航、`-1/-2` 动作空间、需 >70B 的 triage（错误级联 15–19%，我们的目标是 ≤2 次调用直达） |
| 4 | ReadAgent | **采（核心）** | ① 句柄直达原文（词条 → 引文 → 例证）；② gist 用 "shorten" 保叙事顺序，不用 "summarize" 重排；③ 模型自主决定读多少 → browse 的 limit 参数 | 分页算法、迭代重 gist（我们按 seq 区间天然分页） |
| 5 | GraphRAG | **改 + 参** | ① 报告 schema（title/summary/rating/findings）；② `[Data: Node(#), Msg(#)]` 引文格式；③ helpfulness 闸 = 预算控制器 | 实体图、Leiden 社区、离线索引（20–47× 语料成本，与词典重叠且 v1 无全局问答需求） |
| 6 | HiRAG | **改（关键零件）** | **受控概念词表** → 改造为词条 `kind` 分类法（file/command/error/decision/task/api-symbol/topic）——这是"不同卷词条可横向比较"的前提 | 逐层 KG 抽象、`CS_i` 动态层数、跨层最短路径（词典没有"层"，桥留给 v2 跨卷链接） |
| 7 | MemGPT | **参 + 戒** | 分页返回提示（"Showing 10 of N"）→ browse 分页话术；自指检索接口风格 | 主上下文三段管理、working context 函数写、驱逐/换入换出（**宿主 compaction 已做**） |
| 8 | APDMem | **采（结论）+ 弃（架构）** | ① `read_raw` 是精度主力（消融 −5.9%）；② 预算要显式（步数 + token 双上限）；③ **L0 质量门控召回** → 词头质量就是我们的 L0；④ 7 动作收敛为 3 个 | 四层固定物化（L1/L2 中间层：词典义项已替代）、ReAct 控制器循环（在线 124.3k tok/37.7s per question，太贵） |
| 9 | HORMA | **采（核心）** | ① 文件系统式导航（`ls`→kind/前缀浏览、`cat/grep`→词条定位）；② note 带 provenance → 我们的 citation；③ **写侧技能化**（编纂 prompt 当一等领域对象） | GRPO 训练导航（无训练环境）、技能库在线演化（4 轮迭代，重） |
| 10 | ConvMem | **改（思想）** | 关键证据片段"旁路直达输出"→ `dict_cite` 直接回原文 | 逐 query 重算卷积（成本高，且它是生成模型不是记忆索引） |
| 11 | HarnessTheMemory | **采（约束）** | ① 宽召回伤 agentic 决策 → 词典窄查；② 批量/惰性构建先例 → 编纂批处理；③ 路由增益天花板低 → 联合目录精确匹配 | 11 个 substrate 组合实验（无实现可抄） |
| 12 | CoMeT | **弃** | —（仅借"定容 + 淘汰"常识） | 整篇：论文是模型内部 KV/激活双记忆（需微调 + 自定义 kernel），同名包才是文本树；与插件不同构 |
| 13 | GameAgentSurvey | **戒** | "选择性巩固/遗忘是开放挑战"→ 写进风险声明（我们 v1 不做遗忘） | 整篇机制（游戏 agent 经验树，非工作记忆） |

**汇总**：进 v1 设计的结论只有 5 条（RAPTOR 的 collapsed、ReadAgent 的句柄直达、APDMem 的 read_raw/预算、HORMA 的 fs 导航与写侧质量、HiRAG 的受控词表）；其余要么改造成交互契约，要么只当反证/参数参考。

## 3 项目裁决（26 个 → 6 个零件，0 个依赖）

> 原则：**只抄机制，不接依赖**；每个项目问一句"它替我们省了哪行代码"，答不出就弃。

### 3.1 采纳为零件（6 个）

| 项目 | 只取这一个零件 | 用在哪 |
| --- | --- | --- |
| `thedotmack/claude-mem` | 三步渐进检索：search（~50-100 tok）→ timeline → get 全文，每层标注 token 成本 | `dict_browse` / `dict_lookup` / `dict_cite` 的交互与预算标注 |

### 3.3 宿主已有能力重叠，不引入（9 个）

`letta-ai/letta`、`mem0ai/mem0`、`MemTensor/MemOS`、`EverMind-AI/EverOS`、`MemMachine/MemMachine`、`vectorize-io/hindsight`、`topoteretes/cognee`、`basemachines-co/basic-memory`、`modelcontextprotocol/servers`（memory server）

`OpenHands/OpenHands`（Docker 运行时；事件流可回放宿主已有）、`oraios/serena`（符号级检索 → DSH 已有 fs/lsp 工具）、`langchain-ai/langgraph`（检查点 → 宿主 session 已做）、`openai/openai-agents-python`（Sessions/handoff → 宿主已有）、`yzfly/awesome-context-engineering`（清单，不是实现）。

## 4 宿主 DSH：最大的"已有就不重造"清单

奥卡姆剃刀最大的减项不是砍论文，是**别重造宿主已经做完的东西**：

| 能力 | 宿主已有 | 我们怎么做 |
| --- | --- | --- |
| 原文真源 / 历史 | session log（append-only，shadowed 事件仍在） | 只存 seq 引用 |
| 上下文压缩与压力策略 | `ctx.compaction`（阈值/保留/锁/事务） | **只观察事件，不接管**（v1） |
| token 计量 | `ctx.tokenMeter` | 直接用 |
| 跨会话读取 | `ctx.sessionQuery` | 直接用 |
| 提示词注入 | `ctx.systemPrompt.section/context` | 只放凡例 + 缩略目录 |
| 工具注册 | `ctx.tools.register` | 3 个工具 |
| 持久化 | `node:sqlite`（内置） | 4 张表 |
| 大结果外置 | spill 机制 | 不用管 |

## 5 融合结果：v1 最小充分集

| 部件 | 职责 | 融合来源（零件级） | 量级 |
| --- | --- | --- | --- |
| **编典器** `compiler.js` | 从压缩 delta 确定性抽取词条（文件/命令/错误/API/决定）+ 宿主摘要入典 + 词头规范化/合并 + 生成 citation | HORMA 写侧 + APDMem L0 质量 + langmem 幂等配对 + PageIndex 范围映射 + HiRAG 受控词表 | ~400 行 |
| **词条库** `vocabulary.js` | `volumes / entries / citations / compile_runs` 四表；义项修订链；词条上限 | graphiti 双时态 → 义项修订；claude-mem 引用成本标注 | ~300 行 |
| **目录注入** `catalog.js` | 凡例（稳定段）+ 缩略目录（词头表，≤400 tok，版本稳定） | supermemory 静/动分离 + aider 预算 + RAPTOR collapsed | ~150 行 |

## 6 明确不做（"不良则弃"清单）

| 不做 | 为什么（奥卡姆理由） |
| --- | --- |
| 树形结构作为访问层 | 观察式下退化为单链；遍历证据全面劣于压平索引（RAPTOR/ReadAgent/MemTree） |
| 实体图 / 社区摘要 / 全局问答 | 20–47× 索引成本；与词典重叠；v1 无"总结整个项目"需求 → 需要时作 v2 或工具级小功能 |
| embedding / 向量检索 | DSH 无 embedding provider；词典精确查足以验证价值；v1.1 按需加"近义发现" |
| LLM 主题抽取 | 每轮 +1 次调用；先用确定性词条验证"查字典"是否真的有用 |
| 逐层导航动作空间 / ReAct 控制器 | MemWalker 错误级联 15–19%、APDMem 在线 124k/37.7s；目标 ≤2 次调用直达 |
| 树重排 / 剪枝 / 遗忘 | 缓存代价高、学界无定论、无收益证据 |
| 跨树迁移 / 合并 | 资料零先例 |
| UI 卡片 / 词典浏览页 | v1.1，先验证模型侧价值 |
| 外部服务（Chroma/Bun/图库/Docker/MCP memory） | 引入运维面与依赖，插件不该带 server |
| AGPL / 许可不明代码 | 只抄机制不抄代码；basic-memory 等直接不碰 |

## 7 争议项（先不做，给出"加回来"的触发条件）

| 机制 | 触发条件（可测） |
| --- | --- |
| LLM 主题/决定词条 | 确定性词条的 `dict_lookup` 命中率 < 60%（拿 20 个会话内事实题测） |
| embedding 近义发现 | "不知道词"的失败率 > 30%（browse 后仍查不到） |
| timeline 时序视图 | 出现"按时间线回顾"类需求且 browse 兜不住 |
| UI 词典页 | 用户需要人工查阅/编辑词条 |
| 跨卷同词条合并 | 多卷重复词条成为噪声（同一词头出现在 ≥2 卷且内容冲突） |
| 全局总述 | 出现"总结整个项目"类真实任务 |

## 8 奥卡姆自检（每个机制过三问）

1. **不做会怎样？** 答不出"会坏"→ 不做。
2. **宿主能不能替？** 能 → 不写。
3. **能不能写成一个测试断言？** 不能 → 先不写。

v1 的每个部件都能回答：
- 编典器 → 无它则词典空 → 必须有；
- 词条库 → 无它则无法引用与修订 → 必须有；
- 目录注入 → 无它则模型不知道有什么词 → 必须有（且 ≤400 tok）；
- browse/lookup/cite → 无它们则查不到/取不回 → 必须 3 个，不能再多。

**其余全部没有"必须"论证，所以不进 v1。**

## 9 一句话总结

**好机制全吸收，但吸收到"字段 / prompt / 预算 / 测试 / 失败处理"里，不是吸收到"运行时依赖"里；结构只留能过字典筛子的那几块。**
所以准确说法不是"集百家之长"，也不是"只留最少的东西"，而是：**把 13 篇论文 + 26 个项目的设计智慧尽量吸干，用一个字典式的筛子决定"哪些变成我们自己的字段、提示词、验收断言"，只把不可避免的最小结构写进代码。** 这就是奥卡姆剃刀在字典式架构下的具体形态——减的是"多余结构"，不是"知识"。

## 11 因"充分吸收"而加进 v1 的六件事（不增依赖、不增每轮 LLM 调用）

1. **编典 prompt 技能库（HORMA 写侧技能化）**：把"抽文件 / 抽命令 / 抽错误 / 抽决定 / 抽主题"写成 5 条技能规则 + 强制 `improvement` 字段；prompt 版本化、可 A/B、可评估。这是"写侧质量决定上限"的落地。
2. **三级披露（CoMeT 包 T1/T2/T3 + ReadAgent gist）**：`gloss`(T1，≤40 tok) / `senses`(T2，详细释义) / `citations`→raw(T3，例证原文)；`lookup` 默认只给 T1+T2，`cite` 才取 T3——既省 token 又保真。
3. **失败模式矩阵（论文失败模式 → 显式处理）**：幻觉→强制引文；漏词→browse；重复→去重；未收录→显式返回；陈旧→superseded；配对→不切 tool 对。每条进测试。
4. **评测 harness（HTM 方法论 + APDMem 指标）**：随插件发布 `eval/`：20 题固定集 + 指标（查词直达率、平均调用次数、引文保真率、常驻 token、每轮额外 token）。**这是把"先进论文的评测方法"真正吸收成工程件**。
5. **统一引文规范（GraphRAG `[Data:...]` + HORMA note provenance）**：`[cite c3 · seq 120-141 · 12:31]`；每条释义至少挂一条 citation，否则编纂不合格。
6. **可审计导出（EverOS / basic-memory 的"人可读事实源"思路）**：v1.1 把词条导出为 Markdown 供人审阅，不引入其运行时。

> 结论：**"吸收"全量做，体现在字段、prompt、预算、测试、失败处理、评测方法里；"集成"最小做，只留 4 个部件 + 3 个工具 + 0 依赖。** 两者不冲突。
