## 2 架构落地（与 03 方案一致）

```
profile bundle（Host 平面，一行 insert）
└─ apply(ctx)
   ├─ session/event 监听 ── compaction/summary → compiler（异步队列、幂等）
   │                        assistant/message  → usage 埋点（cacheRead/Write）
   ├─ compiler → extract（确定性六类词头）→ vocabulary（去重/引文/上限）→ SQLite
   ├─ agent/pre-step → 结构变化时注入一条窄 digest（step 1、哈希去重、每卷≤40 次）
   ├─ systemPrompt.section → 凡例（静态、稳定；无词典时为空）
   └─ ctx.tools.register → dict_browse / dict_lookup / dict_cite
```

### 2.1 数据模型（`$DSH_HOME/flow-tower/flow_tower.db`，SQLite WAL，schema v2）

- `volumes`：卷（v1 = 会话）、scope、摘要（宿主压缩摘要，clamp 1200 字符）、版本、计数；
- `entries`：词条（headword / norm / kind / gloss / senses / related / tier），`UNIQUE(volume_id, headword_norm)`；
- `citations`：引文（`session_id` + `seq_start/seq_end` + ≤200 字符短摘录），**不存原文**；
- `compile_runs`：编纂幂等（`compaction_id + delta_hash`）；
- `index_meta`：digest 版本 / 内容哈希 / 注入次数；
- `metrics`：用量与编译统计。

### 2.2 关键实现决策（含与 v2 方案的偏差）

| 决策 | 落地 |
| --- | --- |
| 观察式而非替换压缩 | 未 import 任何 `@deepseek-ai/*`；未改 preset；未碰宿主压缩事务 |
| 原文零复制 | 引文只存 seq；`dict_cite` 通过 `ctx.sessionQuery.readSession`（跨会话、含已持久化非 live）或 live Session 回放 |
| 确定性编纂（v1 无 LLM） | 六类词头：文件、命令、错误码/错误句、决定、任务、反引号符号 |
| 义项/修订链 | 字段已建（`revision_of`/`superseded_by`），v1 不产生修订（留给 v1.1） |
| 全局路由视图 | v1 未做 `systemPrompt.context` 路由段；`dict_browse({catalog:true})` 提供联合目录（**偏差**：`routerBudgetTokens` 已从配置移除，保持 11 项、无死配置） |
| digest 注入 | 宿主不会替换/去重注入消息，故：仅 `step===1`、内容 SHA1 去重、每卷最多 40 次（**偏差**：原方案未设上限） |
| 跨会话 | `sessionQuery` 优先，live Session 兜底；两者都不可读时显式降级，不伪造 |
| `nodeBudgetTokens` | 用作单条词条输出预算（`dict_lookup` 返回体 clamp） |
| 无 Config schema | 纯 JS 无法 import schemastery；配置来自 patch row，非法值启动即报错并保持 inactive |

## 5 已知限制（v0.7 更新后）

1. **观察式**：不改变宿主压缩产物；词典在压缩发生后才更新，覆盖受宿主压缩策略影响（一会话一卷）。
2. **无内置 LLM 编纂**：确定性八类词头 + TF-IDF 主题为主；语义主题/人物关系可通过 **agent 提案管线**（JSON→校验→提交，`proposalMode` off/shadow/on）接入外部 agent。
3. **无 embedding/向量语义**：已有 BM25-lite **词法检索**（`dict_search`）与排序候选，仍无语义/跨语言召回。
4. **UI 为只读面板**：v0.7 已有 `/flow-tower/` 词典页（项目/树/时间线/任务/搜索），但无编辑/看板拖拽/多用户。
6. **任务闭环是启发式**：完成语句按 token 重叠关闭 open 任务；同义改写会漏，仍需语义匹配。
5. **digest 会累积**：durable 注入消息无法被宿主替换；已用"仅 step1 + 哈希去重 + ≤40 次"封顶，v1.1 计划改 `systemPrompt.context` 快照。
6. **任务完成度是快照而非闭环**：`open` 与 `done` 按语句独立成词条，未真正回填关闭同一未完成任务（`07` §3 P0）。
7. **长会话会触达词条上限**：真实 460 条消息第二轮即到 500；append-only 无淘汰，需优先级/滚动窗口（`07` §3 P1）。
8. **无 Config schema**：配置仅来自 patch row；改配置需重启生效。项目键按会话 cwd 规范化，目录重命名/迁移会生成新项目库（旧库留在原目录，不自动搬）。
9. **单写者**：SQLite 单进程写入假设；多 DSH 实例同时写同一项目库未验证（WAL + busy_timeout 只能缓解）。
10. **存储位置变更的影响**：默认从 `$DSH_HOME` 迁到项目文件夹后，多项目会产生多份库；旧全局库通过一次性迁移处理，迁移失败会保留原库并在日志告警。

## 8 v1.2 升级说明（六维模型 + 项目本地存储）

- 库 schema v2 → **v3**：`volumes.project`；`entries.module/status/status_seq/first_seen_at/last_seen_at`；`citations.event_time`。真实库已迁移验证（`user_version=3`）。
- 抽取新增 `feature`、任务 `open/done`、`module`、事件时间；词条新增首次/最近时间、共现 `related`。
- 工具 3 → **4**（新增 `dict_timeline`），browse/lookup 增加 project/module/status/since/until。
- digest 升级为五维缩略目录；配置 `maxEntries` 200→500。
- **存储默认改为项目本地**（`storageMode: 'project'`）：`<项目根>/.flow-tower/flow_tower.db`，自动 `.gitignore`；不可写/无 cwd 回退全局库；`dbPath` 可强制单库；旧全局库带 project 的卷自动迁移到项目目录。
- 密钥遮蔽：插件保存的释义/短摘录对常见密钥模式做 `[redacted]`；`dict_cite` 仍逐字回放 session log。
- **升级后**：`remove_bundle` → `install_bundle` 可让 HMR 加载新 JS 模块（本机已验证 v0.2/v0.3），否则重启 DSH。
