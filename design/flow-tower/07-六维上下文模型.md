# 流动塔 · 六维上下文模型（时间 / 项目 / 模块 / 功能 / 任务完成度 ↔ 上下文）

> 日期：2026-11-15
> 回答用户问题：「时间、项目单位、模块单位、功能单位、任务完成度与上下文对应关系有考虑到吗？还有哪些咱们没考虑到的？」
> 结论：**五个维度已落成 schema v3 + 工具参数 + 注入分层**；上下文对应关系按「稳定 → 半稳定 → 按需 → 原文」四层设计。仍缺 20 项，P0 五项列在 §4。
> 实现见 `plugin/flow-tower/`（v1.1 增量）、验收见 `06-实现与验收.md`。

---

## 0 一句话回答

**考虑了五个维度的"存储与访问"，并把它们映射到不同的上下文层**：项目/模块/功能/任务属于"半稳定"信息，只进会话 digest（版本变化才刷新）；时间属于"查询轴"，不常驻、只走 `dict_timeline`/`since-until` 参数；原文永远只在 `dict_cite` 里出现。**不应把五个维度都塞进常驻上下文**——那会同时破坏前缀缓存与"宽召回伤决策"这两条硬约束。

## 1 五个维度 → 存储 / 访问 / 上下文层

| 维度 | 语义 | 存储字段（schema v3） | 访问方式 | 上下文层 |
| --- | --- | --- | --- | --- |
| **时间** | 每条记忆"何时首次/最近出现"；证据的精确时刻 | `entries.first_seen_at/last_seen_at`、`citations.event_time`、`tier`（按 last_seen 计算） | 全部工具支持 `since/until`（ISO 或 epoch ms）；`dict_timeline` 时间轴；`dict_lookup` 引文带时间戳 | **不常驻**：时间轴与时间过滤走工具结果（易变、按需）；digest 只放"最近模块/最近计数"这类聚合 |
| **项目** | 记忆归属哪个 workspace/项目 | `volumes.project`（规范化 cwd，`project:<path>` 的 scope 对齐） | `dict_browse({catalog:true})` 按项目分组；`project` 过滤 browse/lookup/timeline | **半稳定**：digest 一行 `Project: <path>`，只在会话/项目变化时变 |
| **模块** | 代码单元（文件/symbol 所属目录前缀） | `entries.module`（`src/a.ts`→`src`、`src/compiler/x.ts`→`src/compiler`、`packages/core/agent/src/x.ts`→`packages/core`） | `dict_browse({module})`、`dict_timeline({module})`、digest `Recent modules` | **半稳定**：digest 一行最近模块（≤4 个），版本变化才刷新 |
| **功能** | 能力单元（"实现/支持/修复 X"），连接相关文件/决定/任务 | `kind='feature'` + `entries.related`（同消息共现双向链接，≤5） | `dict_lookup(feature)` 显示 `See also:`；`dict_browse({kind:'feature'})` | **半稳定**：digest 只放 feature 计数；明细走工具 |
| **任务完成度** | 工作项的开/关状态 | `entries.status ∈ {open,done}` + `status_seq`（按 seq 单调，新陈述覆盖旧） | `dict_browse({kind:'task',status:'open'})`；`dict_lookup` 显示状态；digest `Open tasks`（≤5）；词头表用 `✓` 标完成 | **半稳定**：未完成任务进 digest（**这是任务完成度与上下文的直接对应**）；完成项只留计数与打勾 |

### 1.1 上下文四层（对应关系总表）

| 层 | 放什么 | 何时变 | 缓存影响 | 预算 |
| --- | --- | --- | --- | --- |
| L0 凡例（`systemPrompt.section`） | 五个维度的用法说明、安全边界 | 几乎不变（插件升级才变） | 最稳定；变一次全局失效 | ≤150 tok |
| L1 会话 digest（`agent/pre-step`，durable 消息） | project、kind 计数、open tasks、最近模块、词头表 | 词典版本变化（压缩后编纂提交） | 每次变化使该会话后续前缀失效；已用 step1 + hash 去重 + ≤40 次封顶 | ≤400 tok |
| L2 工具结果（browse/lookup/timeline/cite） | 任意维度的明细、时间轴、引文句柄 | 按需，不常驻 | 只影响当次请求尾部 | browse 无硬限；lookup ≤900 tok |
| L3 原文（`dict_cite`） | session log 逐字回放 | 永不进常驻 | 无 | ≤12000 tok/次 |

**关键取舍**：
- 时间不常驻 → 避免"每轮时间戳变化"打爆缓存；
- 项目/模块/功能/任务只放"计数 + 未完成项 + 最近模块"→ 既有用又低 churn；
- 明细全部按需 → 对应 HTM「agentic 窄召回」结论；
- 原文只在 L3 → A1 公理（原文零复制/零改写）不变。

## 2 本轮落地（v1.1，schema v3）

### 2.1 存储
- `volumes += project`；`entries += module, status, status_seq, first_seen_at, last_seen_at`；`citations += event_time`。
- 迁移：`PRAGMA user_version 2→3`，逐列 `ALTER TABLE`，回填 project/timestamps/module；**已在真实库 `$DSH_HOME/flow-tower/flow_tower.db` 上验证迁移成功**（列齐全、user_version=3）。
- 新查询：`listProjects`、`listVolumes({project})`、`listEntries({module,status,since,until})`、`openTasks`、`recentModules`、`timelineEntries`、`searchEntries({project})`。

### 2.2 抽取
- 新增 `feature` 种类：中文 `(实现|支持|添加|新增|开发|接入|修复|优化|重构|设计|完善|补齐)X`、英文 `(implement|add|support|fix|...) X`。
- 任务状态：`TODO/FIXME/待办` 等 → `open`；`已完成/修复了/done/fixed` 等 → `done`。
- `module` 从路径推导；候选携带 `time`（事件时间）。

### 2.3 词条
- 首次/最近时间（min/max）；`module` 回填；任务状态按 seq 单调；**同消息共现 → `related` 双向链接**（功能单位与文件/决定/任务关联）。
- `tier` 改为按 `last_seen_at` 计算（时间驱动的冷热）。

### 2.4 工具（3 → 4）
- `dict_browse`：+ `project/module/status/since/until`；`catalog:true` 显示"项目 → 卷"两级。
- `dict_lookup`：+ `project/since/until`；返回 `Project / module / status / Time(first-last)` 与带时间的引文。
- `dict_cite`：不变（原文回放）。
- **新增 `dict_timeline`**：时间轴视图（最近优先，kind/status/module/project/时间窗过滤）——时间维度的专用入口。

### 2.5 上下文
- digest 升级为五维结构：`Project` / `Counts(+open tasks)` / `Recent modules` / `Open tasks` / `Headwords(✓done)` / 用法行。
- 凡例升级为五维说明 + 四工具指引。

### 2.6 验证（v1.1）
- 单测：**17/17 绿**（新增 3 个维度用例：抽取维度、存储维度查询、digest/timeline 渲染）。
- 离线评测：**25 题 PASS**——`hitRate=1`、`citeFidelity=1`、`avgCalls=2`、digest 296 tok、openTasks=1、timelineEntries=29、project 正确。
- **真实会话回放评测**：本机 1.4MB 持久化会话（1414 事件 / 460 消息）两轮编译 → 500 词条（第 1 轮 237，第 2 轮只编增量），六类词条齐全、`project` 正确、`openTasks=1/doneTasks=48`、digest 273 tok、`dict_cite` 逐字命中原文、时间过滤生效。真实数据暴露的两处问题（URL 片段误判为文件、模块未相对项目根）已修复；`maxEntries` 200→500。
- 真实库迁移已验证；**运行态**：`remove_bundle` → `install_bundle`（0.3.0）后 HMR 加载了新模块，新工具与项目本地存储都在运行中会话即时可用；完成五维 + 项目本地存储实时冒烟（项目分组/模块/未完成任务/时间轴/带时间引文/gitignore/旧库迁移标记全部通过；清理后库回空、schema v3）。

### 2.7 项目本地存储（v1.2，用户要求）

**默认把词典放在用户项目文件夹里**，与"编程/其他任务项目"同目录：

| 项 | 落地 |
| --- | --- |
| 默认路径 | `<项目根>/.flow-tower/flow_tower.db`（项目根 = 会话 cwd 规范化） |
| 跨会话 | 同一项目的所有会话共享一份词典；卷仍按 session 分区 |
| 防误提交 | 自动写 `<项目根>/.flow-tower/.gitignore`（内容 `*`） |
| 回退 | 会话无绝对 cwd / 项目不可写 / `storageMode: 'global'` → `$DSH_HOME/flow-tower/flow_tower.db` |
| 单库覆盖 | `dbPath` 强制所有项目共用一个库（便于备份/测试） |
| 旧数据 | 首次加载把旧全局库中带 project 的卷迁移到项目目录并删旧副本，写 `.project-migration-v1` 标记；失败保留原库并下次重试 |
| 多项目 | `dict_browse({catalog:true})` 聚合当前进程已打开的项目库；`project=<路径>` 可按需打开指定项目库 |

**潜在问题优化（本轮同时处理）**：

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 存储挂在 `$DSH_HOME`，不跟项目走 | 改为项目本地（上表），含迁移/回退/gitignore |
| 2 | Windows 路径大小写/斜杠不一致导致项目键分裂 | `normalizeProjectPath`：统一斜杠、盘符小写、去尾斜杠 |
| 3 | 模块前缀把用户主目录当模块、URL 片段误判文件 | 模块改为项目相对推导；过滤 `scheme://` 与域名式片段 |
| 4 | "完成/修复"类句子被误当任务，任务维度被淹没 | 任务只认任务标记或任务完成句式；feature 每条消息最多 3 个、头词 ≤40 |
| 5 | 密钥等敏感文本被摘录进库 | 插件自有摘录/释义对 `sk-*`/`ghp_*`/`AKIA*`/长十六进制等做 `[redacted]`；原文仍只在 session log |
| 6 | 多会话/多项目工具混用 | StoreManager 按项目解析；lookup 当前项目优先、失败跨已打开项目库回退；cite 跨库找 citation |
| 7 | rotate/大小写等路径变体创建重复库 | 项目键规范化 + store 缓存 map 复用 |
| 8 | 长会话词条上限（500）仍会饱和 | 记为已知缺口（P1），下一步做优先级/滚动窗口 |

## 3 还没考虑到的（Gap List，20 项）

> 按"对任务完成度/上下文质量"的收益与实现成本排序。

### P0（下一轮就该做）

1. **任务闭环匹配**：`done` 语句与 `open` 任务目前是两个独立词条，未真正"关闭同一任务"（需要关键词/共现匹配或 LLM 判定）。→ 任务完成度只有"快照"，没有"生命周期"。
2. **预算动态化**：digest 固定 400 tok、lookup 固定 900 tok；未按任务形态（QA vs agentic）与剩余窗口分配（HTM 的双档检索结论）。
3. **项目键稳定性**：project 用绝对路径，目录重命名/迁移会断开；需要 stable project id（如 git remote + 顶层目录）。
4. **时间语义**：无时区/相对时间（"昨天"）、无会话阶段（探索/实现/收尾）、无 `as-of` 全量快照（现在只过滤引文，不重建某时刻的词典视图）。
5. **敏感信息 redaction**：原文与短摘录可能包含密钥/个人信息，目前只有"提示风险"，没有 redaction 过滤。

### P1（值得排期）

6. **模块边界不等于路径前缀**：未识别 package.json / tsconfig / workspace 边界；单仓多包时模块可能合并错误。
7. **功能与模块/测试/决策的"证据级别"映射**：现在只有同消息共现链接，没有"这个功能由哪个文件实现/哪条测试覆盖"。
8. **跨卷同词条合并视图**：联合目录只列卷，不做跨卷合并去重（`dict_lookup` 取首个匹配）。
9. **子代理/任务树映射**：session header 有 `parentSession`/`delegationDepth`，未纳入项目卷与任务树。
10. **审计与可解释性**：有 citations，但没有"为什么这条被注入/命中"的日志与查询接口。
11. **人可编辑/纠正词条**：无 human-in-the-loop 修正入口（写错一次会一直错）。
12. **多模态**：image/file block 在引文里只是占位符，未索引（附件内容不可查）。
13. **数据生命周期**：无卷归档/清理/保留期/vacuum 策略，DB 会随会话无限增长。
14. **多实例并发写**：单写者假设；多 DSH 实例/多机未设计（SQLite WAL 跨进程写有风险）。
15. **上下文覆盖率指标**：未统计"被索引的 seq / 被压缩的 seq"，无法告诉用户"词典覆盖了多少历史"。
16. **长会话词条上限饱和**：真实 460 条消息会话两轮即到 500 上限；append-only 无淘汰，后续新内容会被拒收。需要按 kind 优先级 + 滚动窗口/降级淘汰（或 v1.2 的 LLM 摘要压缩词条）。

### P2（依赖外部条件或产品化）

16. **embedding/近义检索**：需宿主 embedding provider（当前无）；近义词发现是"不知道词"的主要兜底。
17. **UI**：词典浏览页、任务看板、时间线视图（人侧）。
18. **真实会话回放评测 + 开/关 A/B**：现在评测是合成语料；缺真实长会话上的 cache 命中/token 对比。
19. **义项修订链落地**：字段已有，未实现"旧义项 superseded、默认显示当前义项"。
20. **与宿主 goal/todo 集成**：把当前 goal/todo 映射到任务维度，实现"任务目标 → 上下文预算"的直接对应。

## 4 下一轮建议（P0 → v1.2）

1. 任务闭环：同卷内 `done` 候选按共享关键词（≥2 个显著 token）回填最近 `open` 任务，冲突时保留 seq 较新者；加测试。
2. 预算分档：`config.digestProfile = 'agentic' | 'qa'`（agentic 窄、qa 宽），并暴露给 digest/lookup。
3. 项目稳定键：project = `git remote` 或 workspace 顶层名 + 相对路径；迁移时回填。
4. `as-of` 查询：`dict_lookup(term, as_of)` 返回"某时刻之前可见的义项/引文"。
5. 敏感词 redaction：对 `excerpt` 与 `dict_cite` 输出做固定模式的密钥/令牌遮蔽（`sk-...`、`ghp_...`、长十六进制等）。

以上 1–5 项都不需要新增依赖、不需要 LLM，可在当前观察式架构内完成。
