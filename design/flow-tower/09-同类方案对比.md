# 上下文流动塔 · 与项目内其它上下文方案对比（v0.4.0）

> 日期：2026-11-15
> 对比对象：项目内 13 篇论文、26 个开源项目/社区插件（资料见 `papers/`、`references/`、`design/flow-tower/reading/`）。
> 口径：只比"与上下文管理/记忆检索相关的能力"，不做 benchmark 横比（各论文数字口径互不一致，`02` 已声明不采信）。
> 结论先说：**在"项目级、可回溯、零依赖接入 DSH"这条线上我们不弱；在"语义检索、真分层树、跨塔迁移、UI"上仍弱于成熟框架**，差距与路线见 §6。

## 5 我们的独特组合（不比别人弱的地方）

1. **项目本地、跨会话共享**：`<项目>/.flow-tower/`，自动 gitignore，迁移/回退/单库覆盖。
2. **原文无损可回溯**：词条只存 `seq` 句柄 + 短摘录，`dict_cite` 逐字回放 session log（跨会话 `sessionQuery`）。
3. **多维检索面**：项目/模块/功能/任务(open-done)/时间/章节/人物 + 联合目录，4 个工具平均 2 次调用直达原文。
4. **DSH 原生零依赖**：纯 JS、无构建、无外部服务、稳定 seam、fail-soft，压缩后自动编纂。
5. **双栈语料**：技术语料（文件/命令/错误/决定/符号）+ 叙事语料（章节/人物）都有确定性抽取。
6. **规模已实测**：8.4M 字符小说 → 2822 词条、1.3s、2.9MB；1.23M 字符论文合集 → 791 词条、0.48s、1.1MB；查询/引文保真 100%。

## 6 仍弱于成熟方案的地方（不回避）

| 差距 | 对手 | 影响 | 路线 |
| --- | --- | --- | --- |
| 无真分层树/DAG（父摘要→子摘要） | RAPTOR/MemTree/bgx666 | 长文导航不如树形 | **v0.5 已有确定性层级组（卷→kind/module→词条）**；摘要树仍待 v1.5 |
| 无语义/向量检索 | mem0/Graphiti/PageIndex | "不知道词"只能子串浏览 | **v0.5 已加 BM25-lite 词法检索 `dict_search`**；语义/向量待 embedding provider |
| 无 LLM 主题/实体抽取 | Mem0/Graphiti/RAPTOR | 主题级召回弱 | **v0.5 已加 TF-IDF 主题词条**；LLM 主题/关系待 v1.5 |
| 无跨塔迁移/合并 | —（资料也空白） | 项目间记忆不流动 | **v0.5 已加 `tools/merge-projects.mjs`**；双向同步/冲突策略待 v2 |
| 无 UI | bgx666/claude-mem | 人侧不可浏览 | v1.5 词典页/任务看板/时间线 |
| 容量淘汰初级（按 kind+冷热） | MemOS/Letta | 超长会话有信息损失 | v0.5 已加入引文数权重；仍可做任务相关性打分 |
| 单写者 | Graphiti/服务型 | 多实例并发未验证 | v2：WAL 并发策略/多写者协议 |
| 真机 E2E 未覆盖"压缩→自动编纂" | bgx666 已长期运行 | 只到冒烟/回放 | 下一真实长会话验证 |

> **v0.5 更新**：上表前三项（层级/语义检索/主题）与跨塔迁移已做**确定性版本**；与对手的差距从"完全没有"收窄为"没有 LLM/向量/摘要树/UI"。（数据：31/31 单测；离线/真实会话/小说全本评测均 PASS；小说 8.4M 字符 → 2846 词条、保真 100%。）

**结论**：我们不弱在"项目上下文记忆的落地形态"（项目本地、原文可回溯、多维、零依赖、已实测规模）；弱在"语义与层级智能"。前者是产品差异化，后者是 v1.5 的明确路线，不是无解差距。
