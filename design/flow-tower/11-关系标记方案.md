# 11 · 多向关系标记（typed relation graph）方案与实现

> 日期：2026-11-15 · 版本 v0.9.0 · 状态：阶段 0–2 完成（模型 / 边表 / 只读 API / 回填 / 校验 / 导出），阶段 3–5 部分完成
> 依据：用户 12 条设计建议 + 本仓评审修正（单表、宿主指针、provenance）
> 代码：`plugin/flow-tower/lib/relations.js`、`lib/store.js`（schema v5）、`lib/tools.js`（`dict_relate`）、`lib/web.js`（`/api/graph`、`/api/relate`）、`tools/relations.mjs`

## 1 上下文模型对齐

| 平面 | 对象 | 是否作为图节点 | 说明 |
| --- | --- | --- | --- |
| 宿主原始上下文（source plane） | session、message、tool result、compaction | **否**，只做指针 `h:<session>:<seq>` | 宿主拥有、不可变；我们无法也不应管理其生命周期 |
| 派生记忆（memory plane） | entries、volumes、groups、summary_nodes | **是** | 我们拥有、可变、可淘汰；关系挂载在这里 |
| 外部来源 | 合并来源项目、import 文件 | 以 `v:<volume>` 等 ID 引用，可标 external | 校验时允许已知外部端 |

**原则**：不改现有上下文语义；关系是**增量只读层**，不参与 digest/注入（v1 保持缓存行为不变）。

## 2 节点与关系注册表

节点 ID（不可用对象引用，全部字符串）：

| 家族 | ID 格式 | 存在性校验 |
| --- | --- | --- |
| entry | `e_…` | 查 `entries` |
| volume | `v:<volumeId>` | 查 `volumes` |
| host message | `h:<sessionId>:<seq>` | 格式校验（外部，不可回查） |
| group | `grp_…` | 查 `groups` |
| summary | `sum_…` | 查 `summary_nodes` |

关系枚举（`RELATIONS`），带方向、逆关系、成环策略：

| 关系 | 逆关系 | 允许成环 | 语义 |
| --- | --- | --- | --- |
| `parent` / `child` | child / parent | 否 | 层级 |
| `derivedFrom` / `derivedTo` | derivedTo / derivedFrom | 否 | 派生自（含 host seq） |
| `cites` / `citedBy` | citedBy / cites | **是** | 引用（互引合法） |
| `replaces` / `replacedBy` | replacedBy / replaces | 否 | 版本替换 |
| `mergedFrom` / `mergedInto` | mergedInto / mergedFrom | 否 | 合并来源 |
| `sibling` | sibling | **是** | 同层对称 |
| `relatedTo` | relatedTo | 否 | 弱相关（保留，暂不批量产出） |

写入时**逆类型自动规范化**（`B derivedTo A` → `A derivedFrom B`），对称类型按字典序固定端点方向，因此不需要双份存储。

## 3 存储模型（schema v5）

```sql
relations(
  from_id, from_kind, from_volume,
  to_id,   to_kind,   to_volume,
  rel_type,            -- 只存规范方向
  source,              -- compiler | proposal | human | merge | import | migration
  confidence,          -- 0..1
  evidence,            -- JSON: citation ids / seq
  status,              -- active | archived | unknown | external
  note, batch_id, created_at,
  PRIMARY KEY (from_id, to_id, rel_type)
)
索引：from_id, to_id, (from_volume,status)
relation_batches(batch_id, kind, volume_id, stats, created_at)  -- 可回滚
kv(key,value)                                                  -- 同步水位线
```

**outgoing / incoming 是查询，不是双份存储**：`outgoing = WHERE from_id=?`，`incoming = WHERE to_id=?` 并把关系名显示为逆关系。这样从根上排除"两边没同步"的不一致。

## 4 写入与自动维护

| 位置 | 行为 |
| --- | --- |
| `addRelation(store, edge)` | 唯一写入口：校验类型/自环、规范化方向、幂等 upsert、写 batch_id |
| `syncRelations(store, volumeId)` | 从权威数据增量回填：`citations` → `entry derivedFrom host seq`；`revision_of` → `entry replaces entry`；用 `kv` 水位线避免全量扫描 |
| 编译钩子 | 每次压缩编纂后 `relationsMode !== 'off'` 则 sync（try/catch，失败只告警，不影响主流程） |
| 淘汰/删除 | `evictOne`/`deleteEntry` 把相关边标 `archived`（不物理删除，避免丢失历史） |
| 跨塔合并 | 预留 `mergedFrom` 批量边（merge 工具，后续接入） |

## 5 校验、防环与降级

- `validateRelations(store, {volumeId})`：未知类型、悬空端点、外部端豁免；
- `findCycles(store, type)`：对非成环家族做 DFS 环检测；`cites/sibling` 显式允许环；
- 未知关系类型在 import 时**保留**（status=`unknown`），不丢数据、不阻断；
- 关系写入/同步失败一律 fail-soft，只记录 warn。

## 6 序列化与导出

- `exportGraph(store)` → `{ version: "relations.v1", relations: [...], nodes: [...], edges: [...] }`；
- `importGraph(store, graph)`：幂等合并、未知类型保留、批次审计；
- `toDot(graph)` / `toMermaid(graph)` 生成可视化文本；
- CLI：`node tools/relations.mjs --project=<root> --sync|--validate|--export=file [--format=json|dot|mermaid]|--import=file|--rollback=<batchId>`。

## 7 API 与工具

- 工具：新增 **`dict_relate`**（第 6 个）：`term`/`node`/`direction=both|outgoing|incoming`/`limit`；缺失边时自动增量同步一次；
- Web：`GET /flow-tower/api/graph?format=json|dot|mermaid`、`GET /flow-tower/api/relate?term=|node=&direction=`；面板新增 **Graph** 标签（Mermaid 文本）；
- 现有 5 个工具、digest、注入行为**未改动**。

## 8 实测与测试

- 单测 **44/44**（新增关系用例：规范化/幂等、出边入边逆关系、成环策略、增量同步、导出导入 round-trip、未知类型、悬空校验、`dict_relate`）；
- 真实工作区库：`--sync` 产出 **1490 条边 / 1484 词条**；`--validate` **0 issues**；导出 Mermaid `.flow-tower/graph.mmd`（1704 节点）；
- 离线评测 PASS（49 词条）；默认 `relationsMode: 'shadow'`（建图 + 只读查询，不影响现有行为）。

## 9 未完成 / 后续

| 项 | 状态 |
| --- | --- |
| 阶段 3 完整性：`parent/child` 组边、`mergedFrom` 自动边、恢复/归档策略 | 部分（parent 待接入；mergedFrom 预留） |

## 14 v0.14.0 更新（自动化定位：移除人工标注）

产品定位调整：本工具是**自动化智能上下文管理**，不提供人工标注/精修入口。

| 项 | 变更 |
| --- | --- |
| 人工标注 API | **删除** `POST /api/relation/{add,remove,batch,undo}`（请求 404）；`addRelationChecked/removeRelation` 仅保留给测试/未来自动化路径，不暴露 HTTP |
| 面板编辑表单 | **删除** Graph 内的添加/删除/批量/撤销表单；保留只读查看、拖拽、strong 过滤、All projects、导出 |
| 关系来源 | 只允许自动来源：`compiler`（citations/parent）、`merge`（mergedFrom）、`migration`（relatedTo 回填）；**禁止 human 写入面** |
| 模式语义 | `relationsMode: off|shadow|on` 只控制建图与校验/日志（`on` 额外在 digest 显示关系计数），不再影响写权限 |
| 测试 | 单测 **46/46**（删除人工标注用例，新增"annotations 404"断言）；离线评测 PASS |

**保留的自动化能力**：编译后自动生成/同步关系（水位线）、环检测校验、跨进程锁、批量导入/导出、置信度过滤——全部无需人工操作。
