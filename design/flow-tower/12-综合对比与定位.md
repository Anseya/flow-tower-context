## 6 综合定位

### 6.1 我们强在哪（差异化）

1. **项目本地 + DSH 原生 + 零依赖**：`<项目>/.flow-tower/`，会话共享，无外部服务，插件即可用；
2. **自动化**：压缩事件驱动，无人标注、无 LLM 调用（LLM 提案是可选的**外部**生成器，走校验管线）；
3. **原文无损回溯**：词条只存 seq 句柄，`dict_cite` 逐字回放；研究方案里少见的工程级保真；
4. **多维检索面**：项目/模块/功能/任务/时间/叙事/关系，6 个工具平均 2 次调用直达；
5. **关系图工程化**：类型化边、逆关系、环策略、水位线同步、导出/导入、十万边基准、跨进程锁；
6. **规模已实测**：8.4M 字符小说 2846 词条/保真 100%；1484 词条/8257 边真实库；10 万边基准 PASS。

### 6.2 我们弱在哪（诚实）

1. **语义智能**：无神经 embedding、无 LLM 主题/关系抽取（词法是可解释替代，但跨语言/同义弱）；
2. **递归摘要树**：只有确定性分类/摘要 3 层，没有 RAPTOR/MemTree 的递归摘要节点；
3. **生态/UI**：只读面板 vs bgx666 的卡片/树视图、mem0/Graphiti 的完整平台；
4. **多实例并发**：锁+退让，不是多主合并；
5. **真机压缩端到端**：只验证过本仓真实压缩一次，缺少长期多会话统计。

### 6.3 分档结论

| 档位 | 方案 |
| --- | --- |
| **T1 平台/生态** | mem0、Graphiti、Letta（平台成熟、语义强，但非 DSH 原生、成本/依赖高） |
| **T1 DSH 深度集成** | **本工具**、bgx666、qinghuaju（三者各有强项；本工具在自动化/引用/关系图/多维/规模证据上最全，在树 UI 上不如 bgx666） |
| **T1 研究机制** | RAPTOR、MemTree、GraphRAG、APDMem（机制领先，工程落地/DSH 集成弱） |
| **T2 专用/辅助** | ReadAgent、HORMA、aider/Serena/PageIndex 等（单点强） |

**一句话**：若目标是"给 DSH 一个自动、可回溯、项目级、零运维的上下文记忆层"，**我们目前是候选里最完整的**；若目标是"最强语义智能/平台生态"，仍应参考 mem0/Graphiti/RAPTOR 的路线补齐 v1.5（LLM 主题/关系 + 向量检索 + 递归摘要）。
