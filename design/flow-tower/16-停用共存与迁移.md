# 16 · 停用、共存与迁移说明

> 版本：0.25.0 · 面向前台用户/运维
> 结论：**不想用时一条命令停用，数据留在项目里；和其他上下文插件不会直接互相破坏，但不建议同时开两个（会抢注意力/重复注入）。**

## 1 暂时不用了，怎么关？

| 目标 | 操作 |
| --- | --- |
| 临时停用（保留数据） | `plugin_manager remove_bundle target=@local/flow-tower` |
| 重新启用 | `plugin_manager install_bundle target=E:\dsh-plugins\flow-tower`（或 tarball） |
| 只关某一能力 | 设置里：`relationsMode: off`（关系图） / `digestMode: off`（上下文注入） / `llmCompiler: off` / `proposalMode: off` |
| 清空某项目数据 | 删除 `<项目>/.flow-tower/`（会话原文不受影响） |
| 彻底卸载 | 先 `remove_bundle`，再删除插件目录/包；数据在各项目 `.flow-tower/`，按需刪 |

面板/工具消失后，模型不会再收到词典 digest，也不会写入新词条；已有 `.flow-tower/flow_tower.db` 不影响项目本身。

## 2 会不会和其他上下文插件冲突？

**直接冲突：基本不会。** 本插件是 Host-only、旁路观察式：

| 资源 | 本插件占用 | 冲突面 |
| --- | --- | --- |
| 压缩后端 | **不改**（只监听 `compaction/summary`） | 其他插件若替换压缩引擎，事件仍发出则我们继续工作；若不再发事件，我们停止编纂（不会报错） |
| 工具名 | `dict_browse/lookup/cite/timeline/search/relate` | 名字独有，不会覆盖其他插件工具 |
| Web 路由 | `/flow-tower` | 唯一前缀，不会覆盖 |
| 侧栏入口 | `sidebar.footer.action` id=`flow-tower` | 各插件各占一个 action |
| 数据库 | `<项目>/.flow-tower/flow_tower.db` | 各插件独立库，互不读写 |
| 注入 | 每轮首步 digest（≤400 tok，版本变化才注入） | **多个上下文插件会各自注入** → token 成本/注意力竞争 |

已纳入考虑但**未做真实双插件联测**的部分：bgx666 用 patch 改压缩引擎；若两者同时启用，压缩事件是否仍按我们预期发出需实测；qinghuaju 是旁路捕获+注入，和我们的 digest 会重复注入。**建议同一 profile 只启用一个上下文记忆插件**；需要 A/B 时用不同 profile 或不同项目文件夹。

## 3 想换用其他插件/迁移数据

- 导出本插件数据（JSON，含卷/词条/引文/关系图）：
  ```powershell
  node tools/export-data.mjs --project=<项目根> --out=<导出文件.json>
  ```
- 导入到其他插件：**目前没有通用格式**；本导出用于备份/自查，或作为自写迁移脚本的输入。
- 关系图可单独导出：`node tools/relations.mjs --project=<root> --export=graph.json`（或 DOT/Mermaid）。

## 4 推荐实践

1. **一个 profile 只开一个上下文插件**（避免重复注入与工具冗余）；
2. 试用新插件前先 `remove_bundle` 停用本插件，保留数据；
3. 多个项目共用插件没问题——数据按项目隔离在 `.flow-tower/`；
4. 面板/侧栏入口名称是"**上下文记忆**"（悬浮提示：上下文流动塔 Flow Tower），点击打开项目词典；
5. 不想让侧栏出现入口但保留工具：在插件管理里停用即可（Client 入口随插件一起消失）。

## 5 已知边界

- 与 bgx666 同时启用时，两者都会尝试观察/影响压缩；**未实测**谁能优先、事件是否重复，建议只留一个；
- 多个注入型插件同时启用会增加 prompt token，可能影响前缀缓存；
- 本插件没有"暂停注入但保留工具"的独立开关（可用 `digestMode: off` 达到近似效果）。
