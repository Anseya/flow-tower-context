## 2 机制层拆解

### 2.1 RAPTOR：离线、自底向上、GMM 软聚类

**数据结构与构建**
- 叶 = 连续 **100-token** 段；句子超限时整句移到下一块而非截断（171–174 行）；嵌入 = SBERT `multi-qa-mpnet-base-cos-v1`（175–176）。
- 聚类：GMM + **soft clustering**，"节点可属多个簇、无需固定簇数"（193–196）——**所以 RAPTOR 名义是 tree，实际是有多父的 DAG**（00 未记录，补强）。
- 降维/分层聚类：UMAP 的 `n_neighbors` 分两档使用，先找全局簇、再在全局簇内做局部聚类（210–216）；簇数用 **BIC** 选，`BIC = ln(N)k − 2 ln(L̂)`（220–225），再用 EM 估均值/协方差/权重（226–227）。
- 递归：某簇拼接后超过摘要模型 token 阈值，就在**该簇内递归聚类**（217–219），直到 "further clustering becomes infeasible"（180–181）。停止条件、层数上限、每层节点数原文均未给（事实边界）。
- 摘要模型 `gpt-3.5-turbo`（236）；prompt 极短：system `You are a Summarizing Text Portal`，user `Write a summary of the following, including as many key details as possible: {context}:`（1081–1088）。

**伪代码（附录 F，不能照抄）**
- Alg1 `TRAVERSETREE(tree, query, k)`（1135–1148）：**按印出的伪代码跑不通**——`for layer` 循环里只对 `Scurrent` 打分、排序、赋回，没有"进入子节点"这一步，且返回的 `S0…Sk` 从未定义。必须按正文 249–271 的描述实现（根 top-k → 只在其子集中选 top-k → 逐层累积拼接）。
- Alg2 `COLLAPSEDTREE`（1161–1179）：`total_tokens` 自增写在 `if` 之外（1172–1176），**被预算拒收的节点也计入预算**；实现时跳过节点不应计费。

**两策略实验差异**（QASPER 20 stories，287–294）
- 结论：collapsed tree 持续更好（"The collapsed tree approach consistently performs better"）。机制解释：traversal 固定 d/k 时"每层节点比例恒定"，无法随问题改变高层主题与细节的比例（292–294）——这是**信念式解释**，论文未做归因实验。
- 主结果：collapsed + **2000 tokens**（≈ top-20 节点），UnifiedQA 用 400 tokens（305–322）。Figure 3 无数字，只有图像（事实边界）。
- 附录反例：正文 Table 8（599–617）3 层全树从 L2 起 73.68 vs 只查叶 57.9 → "全树更优"；但 Table 14（Story 2，1334–1350）3 层从 L2 起 **47.1 < 只查叶 58.8**，Table 15–17 又是正例 → **"全树恒优"不成立，是 story 级波动**（单 story 精度，无 n/方差/检验；由 73.68%=14/19 这类比例可反推每题约 19 问【推断】）。
- 非叶节点贡献：collapsed 检索中被选中的节点有 **18.49%–57.36% 来自非叶层**（1400、1406–1422；DPR+NarrativeQA 最高 57.36%）。

**成本与压缩**：摘要/子节点压缩比 **0.28（72% 压缩）**；平均摘要 131 tok、子节点 85.6 tok、每父 6.7 子（1038–1077）；构建 token 与时间对文档长度**线性**（12.5k–78k tok，Apple M1 16GB，977–1005）。

**失败模式**：4%（6/150 节点，抽 40 story）摘要有轻微幻觉，多来自训练先验或错误外推；**未传播到父节点**、对 QA 无可察影响（240–243、1096–1131）；collapsed 需对所有节点做余弦（298–300，靠 FAISS 缓解）；**全文无任何更新/增量机制**（grep 0 命中）。

### 2.2 MemTree：在线、自顶向下增量、严格树

**数据结构**：`v = [c_v, e_v, p_v, C_v, d_v]`；根 `v0` 是结构节点，`c=∅, e=∅`（202–215）。严格树，最贴合 01 里"树是数据结构"的定位。

**插入（Alg1 895–926 + 正文 233–295）**
1. `e_new = f_emb(c_new)`；
2. `INSERTNODE(v0,…)`：若 v 是叶 → **就地膨胀为父节点**，原内容变成它的子节点（245–247、903–907）；
3. 与 v 的所有子算 cosine，取 `v_best / s_max`（909–911）；
4. `s_max ≥ θ(d)` → **先把父内容 `Aggregate(c_v, c_new)`、更新 `e_v`，再递归子节点**（913–919）；否则在当前节点下挂新子（921–924）。
- 关键副作用：每次插入沿路径**重写所有祖先**（256–278）；平均 **3.27 ± 2.38 次 LLM 调用/插入**（1224–1250），单次插入约 10 s；对照 RAPTOR/GraphRAG 全量重建 >1 h、约 3753/3858 次调用（718–721、1232–1250）。父节点更新可在 CPU 并行（275–278、714–716）。
- 叶膨胀会让**已有内容的 depth +1**（245–247）——层级不是稳定属性，这对节点 ID/缓存键很关键（见 §4.1）。

**θ(d) 的真实公式（对 00 的实质更正）**：主文写 `θ(d)=θ0·e^{λd}`（250–255），A.3.7 也重复并给 `θ0=0.4, λ=0.5`（1335–1336）；但 **A.1.3 给出实现式**：`threshold = base_threshold × exp(rate × current_depth / max_depth)`，`base=0.4, rate=0.5`（956–970）。按主文式，在实测 max depth 13 的树上 **d≥2 时阈值就 >1**（d=2：`0.4e^{1}≈1.09`；d=3：`0.4e^{1.5}≈1.79`），任何余弦相似度都不可能满足 → **只有 A.1.3 的归一化版本自洽**。00 第 54 行引用的是主文记号，不能照抄进实现。

**Aggregate prompt（927–955）**：两段输入（New Information / Existing Information "from {n_children} previous entries"）；规则 "If the number of previous entries … (more than 2), focus on summarizing more concisely, only capturing the overarching theme, and getting more abstract"。**只有软约束，无硬 token 上限**。

**检索**：collapsed（307–311）：embed q → 与**全部节点** cosine → 过滤 `θretrieve` → top-k。`θretrieve` **原文未给值**（事实边界）；定性示例实际入选相似度低到 **0.421**（A.6/A.7 全表 0.42–0.72，1852–2081），说明过滤很松或未启用【推断】。
- 预算：MSC `k=3` + **1000 tok**；MSC-E `k=10` + **8192 tok**；MultiHop/QuALITY 沿用 8192（973–977）。切块：MSC 逐轮不切；QuALITY **512 tok** 不重叠；MultiHop **1024 tok** 不重叠（1000–1006）。

**形状与效率**：MultiHop（609 文档）→ 3164 节点 / 1706 叶 / 1458 分支节点，max depth **13**、avg depth **4.9**、分叉 **2.1**、高宽比 6.5（682–698）。正文 670 行写 "3,154 nodes" 与 Table 5 的 "3,164" **自相矛盾**（引用以表格为准）。节点文本长度随深度上升：depth 1 中位 >200 tok → depth 10+ 约 800 tok（674–676）。

**结果口径（别把摘要当结论）**：MSC 短对话（<1k tok）直接全量历史 95.6 最好，MemTree 84.8 > MemGPT 70.4、MemoryStream 84.4（379–409）；MSC-E 200 轮 MemTree 82.5 > MemoryStream 80.7 > 全量 78.0（410–446）；QuALITY（Llama-3.1-70B）：全文 65.1 > GraphRAG 62.8 > **MemTree 59.8 ≈ RAPTOR 59.0** > MemoryStream 43.8（480–543，作者自述 "matches the offline performance of RAPTOR"，540 行）；MultiHop：RAPTOR 81.0 > MemTree 80.5 > GraphRAG 78.3（560–667）。摘要里 "surpassing RAPTOR"（145–148）只在 QuALITY-Hard 子集上有明显幅度（56.5 vs 53.0），overall 仅 59.8 vs 59.0，且作者自己写 "matches"（540）——**MemTree 的卖点是在线可增量 + 近似离线**。

**检索与阈值消融**
- collapsed vs traversal（1252–1283）：traversal `k=10` ≈ collapsed；**`k≤5` 显著掉分**，原因是过早窄化搜索空间、父节点信息重复、深层细节没被访问、上下文被父摘要耗尽。→ 与 RAPTOR 292–294 是同一结论的两个侧面。
- θ 参数（1330–1418）：`θ0=0.8` → 多数节点在 depths 1–2；`0.4` → 4–6；`0.1` → 8–14；λ 从 0.25→0.75（θ0=0.8）只让 max depth 15→11；**下游 accuracy 差异不显著**（1415–1418）。

**失败模式**
- 定性两例（1699–1705）：A.8 "证据在长上下文里被埋没"（检索到了但抽不出来）、A.9 "证据不足"（FTX/Alameda 题只召回母公司）。
- A.6/A.7 暴露 **祖先-后代重复**：同一事实（Bears 16-13 胜）在 A.6 的 10 条检索结果里出现 **5 条**（父/子/叶各层重复入榜，1852–1902）→ 压平检索对树有固有冗余浪费。
- 顺序增量天然偏向近期（526–529："inherently favors more recent conversations"）。
- **无遗忘/剪枝/删除/版本/冲突解决**（grep 仅命中 baseline 描述 168/359 行）。

### 2.3 MemWalker：离线建树 + 逐查询 LLM 导航

**两阶段**（105–112、163–192）：建树 **query-independent，可预计算**（166–168）；导航逐查询。00 第 72 行把它归为"逐查询计算"不准确（见 §3.2）。

**建树**：分段 `c1..cn` → 叶 `s^1_i=LLM(c≤i)` → 上层 `s^{l+1}_j = LLM(s^l_i … s^l_{i+M_t})` 直到 root（177–190）。真实超参：**M_t=8/5/8，段长 1000/1000/1200 tok**（QuALITY/SummScreenFD/GovReport，369–373）。基础模型 Stable Beluga 2（70B LLaMA-2），**4096 上下文**，top-p，zero-shot（365–373）。
- 父节点内容：A.1.1 说把 `[CHILD SUMM NODE]` **拼接**即为父内容，只在超预定长度时才二次压缩（`Compress each summary into a much shorter summary.`，769–775、796–797）→ **上层节点不是"再摘要"而是拼接**，与 RAPTOR/MemTree 的父节点聚合语义不同（补强；直接决定上层 token 会膨胀）。分组规则（是否连续）、层数上界、二次压缩的长度的具体值原文未给（事实边界）。

**导航动作空间**（256–293）
- 非叶：看到下一层摘要集合，动作 = `|M_t|` 选子 **+ 1 回退父**；叶：**2 动作**，commit 作答（`-2`）或 revert（`-1`）；响应 `r=(reasoning, action[, answer])`。
- 工作记忆 m：携带已访问节点内容，按上下文窗截断（287–293），在 prompt 里是 `[WORKING MEMORY]` 槽（221–225）。
- 解析失败：格式不符要求**重新生成**；连续 **3 次**不可解析 → 终止并返回 **"no answer"**（283–286）。"no answer" 是合法终止态，不是重试信号。
- **triage prompt 原文（可抄）**：query + `Summary 0..N` 子节点摘要 + "Which of the following summary is MOST LIKELY to contain information about the answer? First provide reasoning to compare the summaries before you make the decision." + 固定输出 `Reasoning: … / Action: 0/1/2…`（Table 1 200–244、Table 5 798–812）。
- **leaf prompt 原文（可抄）**：`Story background information: [WORKING MEMORY]` + `Main text: [TEXT OF SEGMENT]` + query(+选项) + "If the answer CANNOT be inferred … reply with action -1 / CAN be inferred … action -2" + 固定格式（Table 1 221–243、Table 5 813–827）。

**结果与边界**（Table 2，324–362）：QuALITY 67.4/73.6、SummScreenFD 67.3/64.5、GovReport 59.4/60.4（Orig./Long）。**短文本不占优**：QuALITY Orig. 全上下文右截断 70.1 > 67.4；GovReport Orig. 左截断 59.4 = 59.4；只在 Long 子集全面胜出（473–477、399–401）。效率：平均只读原文 **63%–69%**，成功路径 59%–64%（570–594）；回退出现在 **15.0/18.6/18.8%** 的路径，其中 **70.0/59.6/79.0%** 能救回（516–533）；**去掉工作记忆掉 5–13%**（513–562）。

**失败模式**：建树随序列变长不可扩展（619–624，作者建议树+hash 混合）；**强依赖推理能力**——需 >70B 指令微调（625–628）；13B 加 reasoning 反而更差（QuALITY 39.6 vs 48.1，404–439）；一次导航错误会级联（493–494）。

### 3.2 更正（必须改，带证据）
1. **θ(d) 公式（00 第 54–55 行）**：不能写成 `θ(d)=θ0·e^{λd}` 并用 `θ0=0.4, λ=0.5` 直接实现。原文主文与 A.3.7 虽然这么写（250–255、1335–1336），但 **A.1.3 的实现式是 `θ=0.4·exp(0.5·current_depth/max_depth)`**（956–970）。主文式在 max depth 13 的实测树上 d≥3 就 >1，物理上不可能满足——主文公式只是记号简化。
2. **00 第 55 行 "θ0 从 0.8→0.4→0.1 会让树从 1–2 层变到 8–14 层"**：原文说的是"**大多数节点分布在** depths 1–2 / 4–6 / 8–14"（1405–1411），不是"树的总层数 = 1–2 到 8–14"；而且 **accuracy 差异不显著**（1415–1418）。可以保留"形状由内容长出来"的定性含义，但不要暗示调 θ 能换来性能。
3. **00 第 45 行"压平胜过下钻"的边界**：原文只测了 **20 个 QASPER story**，Figure 3 无数字；且 MemTree 的检索消融显示 traversal `k=10` 与 collapsed 相当、只有 `k≤5` 才显著掉（1252–1283）。正确表述："**每层固定小 k 的逐层下钻**不如压平；k 足够大时二者相当"。
4. **00 第 72 行把 MemWalker 归入"逐查询计算"**：原文明确建树 query-independent、可预先计算（166–168）；逐查询的只是**导航**。措辞更正为"离线建树 + 逐查询导航"。

### 3.3 补强（00 未记、实现要用）

5. MemTree **3.27±2.38 次 LLM/插入、10 s/插入**；对照 RAPTOR/GraphRAG 重建 3753/3858 次调用 >1 h（718–721、1224–1250）——这是"在线 vs 离线"最硬的工程差。

8. MemTree 顺序增量**偏向近期**（526–529）。
9. MemTree 数字矛盾：正文 670 行 "3,154" vs Table 5 "3,164"；A.3.6 把"更深=更长"解释成"more abstract/overarching"（1317–1319），与正文 658–664/706–711 "deeper = more specific" 措辞冲突（引用时以正文任务叙述为准）。
10. MemWalker 真实超参：`M_t=8/5/8`、段 1000/1000/1200 tok、4096 上下文（369–373）；**父节点 = 子摘要拼接**（769–775、796–797）。
11. MemWalker 的 **3 次解析失败 → "no answer"** 终止（283–286）、stray 15–19%/recovery 60–80%（516–533）、工作记忆 −5~13%（513–562）、短文本不占优（399–401、473–477）。
12. 跨论文的一条**可执行规则**：collapsed 胜在"粒度自适应"，traversal 败在"每层 k 固定"（RAPTOR 292–294 + MemTree 1264–1283）——直接决定 DSH 下钻工具的返回策略（§4.3）。

### 4.2 触发时机（四类流动的落点，对齐 01 §8.1）

1. **① 垂直上浮**：沿用 `mergeUp`（engine.js:394–441，阈值 9/3/8 在 index.js:107–110）。论文给出的目标区间是 **6.7–8 子/父**（RAPTOR 6.7、MemWalker M_t=8），9 略高但不离谱；建议把 `children per parent` 做成可观测指标而不是死磕常量。【推断】
2. **② 结构自适应**：**禁止每轮触发**。MemTree 每次插入 3.27 次 LLM、沿路径全父重写（1224–1250）；DSH 若每轮做一次等价操作，成本 ≈ 每轮多 3–13 次调用。只在压缩事务提交时或显式"重排"后台任务里做（对应 01 的静默期）。
3. **③ 时间冷热**：只改元数据（tier），**不得进入 systemPrompt 的路由视图**（否则每次 tier 变化都打前缀缓存，见 4.4）。
4. **④ 跨树迁移**：资料空白（三篇 + 00 的 13 篇都无），第一版不做，与 01 §8.4 建议一致。

### 4.3 prompt 位置与下钻契约

- **systemPrompt**（index.js:52 / 630–642）：放"多树规则 + 分总层路由视图"（tower_id / 一句话画像 / 时间范围 / 预估下钻代价）。**极窄、低频变更**；活跃度、token 数、节点计数等易变值一律不放。
- **checkpoint digest**（text.js:205–216）：放"本树活跃根节点摘要"，多树时按 tower 分组。DSH 的 checkpoint 是**单条 user 消息**（text.js:196–197），可被逐字复用（engine.js:189–197），这是缓存设计的支点。
- **工具返回**：对齐 MemWalker 的 **triage + leaf** 两段契约——一次下钻返回"该节点下一层所有子摘要（triage 列表）+ 当前路径工作记忆"，并附 `parent_id` 允许回退；不要只返回一个节点的正文。理由：MemWalker 回退率 15–19%、救回率 60–80%，无工作记忆掉 5–13%（516–533、513–562）。
- **总述视图**：按需生成、带版本、进工具结果/UI 卡片，**绝不回写路由字段**（01 §8.2 硬规矩）。

### 4.4 前缀缓存影响（流动塔最主要的工程代价）

**现有机制（已核）**：engine.js 的 progressive prefix——倒序发请求，第一发最长，后续逐块缩短以复用前缀（8–12、204–217）；当 surface 已有 checkpoint 时**逐字保留原 checkpoint 消息**而不是重渲染树节点，让 live 会话前缀也能命中（189–197）；`smoke.test.js:190–193` 已断言"live checkpoint message must be replayed verbatim"。

**推论（可以直接写进设计约束）**：
- systemPrompt 位于整个前缀最前 → **路由视图任何一次变更 = 整段会话前缀作废**；
- checkpoint 是 user 消息 → 其变更只让"该消息之后的保留尾部"重算，代价小于 systemPrompt；
- 因此：(a) 路由视图只在**树创建/合并/归档**时变；(b) 结构变更统一放在压缩事务内，与 checkpoint 替换共用同一次 cache reset；(c) 总述/活跃度/统计等易变信息只走工具结果，绝不进 systemPrompt。
- **不变量**：若本次 run 没有结构变更，checkpoint 文本必须逐字不变（可由 4.6 的测试守住）。流动塔的②结构自适应一旦在压缩事务外发生，就会破坏这条不变量——这正是 MemTree"每次插入沿路径重写父节点"（256–278）在 DSH 里的代价形态。

### 4.6 验收断言（把论文结论变成测试）

1. `explore_memory_tree` 单次返回必须含"子节点摘要列表 + 当前路径工作记忆 + parent_id"；只有 node_id→正文的返回，等价于 MemWalker 的 leaf 但缺 triage，会复现 k≤5 traversal 的掉分模式（MemTree 1264–1283）。
2. 单次下钻回包设 token 上限（建议 1000–2000 档），且**同一事实的父+子+叶不得重复打包**（MemTree A.6 反例：同一 "Bears 16-13 胜" 在 10 条结果里出现 5 条，1852–1902）。
3. 结构变更只允许出现在 compaction run 内；测试"无结构变更时 checkpoint 消息逐字不变"（扩展现有 `smoke.test.js:190–193`）。
4. 节点内容必须在**写侧硬 clamp**（字数/token 上限），不依赖 Aggregate prompt 的软提示（MemTree 927–955）。
5. 路由视图字段白名单测试：出现 activity / token 计数 / 时间戳等易变字段即 fail（4.4 不变量）。
6. 回退动作可用性测试：下钻结果能回到父节点，且工具返回带"当前已读路径"（MemWalker 契约）。
