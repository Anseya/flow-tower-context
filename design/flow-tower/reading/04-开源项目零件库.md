### 1.1 五条路线一句话（来自目录 README 第 2 节的一手归纳）

- 分层树/金字塔索引：上层摘要只导航、原始文本无损留叶层，按查询复杂度决定下钻深度。
- 长期记忆框架：把「抽取式事实 / 双时态图谱 / Agent 自管记忆 / 记忆操作系统 / Markdown 即事实源」分得很开，选型先问「写入路径谁控制、失效怎么做、原始证据留不留」。
- 上下文压缩/裁剪/卸载：同一会话内不超窗，核心分歧是「可回滚（cline/OpenHands）vs 不可恢复（LLMLingua）」。
- 结构化索引/JIT 检索：用符号图或目录树代替全文，模型按地图定位、按需读原文。
- 会话状态/持久化编排：checkpoint + thread_id 让任务比进程活得久，是「回滚」的现成骨架。

## 3. Top 5 必抄零件（含落地位置与验收）

### 3.1 原文锚点：ID ↔ 字节/行范围双向映射（#1+#2+#3）
- **为什么必抄**：「原文无损可回溯」不是口号，是这五个里唯一能证伪的契约。PageIndex 的 md→行号切片（A 级，本地可核）证明「树上只存标题+行号、正文留在文件」在实践上可行；graphiti 的 episode 溯源补上「会话消息侧」的原始锚点。
- **落地位置**：`store.leaf_ref{file,line_start,line_end,sha256}`＋`TreeIndex.get/path/range()`；叶层不存全文，只存范围；`tools.get_source(node_id)` 按范围返回原文。
- **验收**：随机抽 20 个 `node_id`，重取原文与其 markdown 切片**逐字节一致**；节点被重摘要 3 次后，旧 `node_id` 仍可下钻（append-only）。
- **不抄的部分**：PageIndex 的「LLM 推理式检索」不抄（要求顶级 chat 模型逐层推理，贵且慢），只抄索引结构与取回。

### 3.2 压缩事务边界三件套：配对保护＋幂等 ID＋原子替换与结果实测（#8+#9+#14+#13）
- **为什么必抄**：流动塔每次上浮/重摘要都是一次「替换历史」的事务，出错就是上下文损坏。langmem 给出切点侧保护（A 级），openai-agents 给出提交侧原子性（A 级），OpenHands 给出「结果是否真的生效」的判定（A 级）。
- **落地位置**：`compaction/{cut_guard,run,commit}.ts`：切点前 `ensure_tool_pairs`；run 记录 `summarized_ids` 且重复即抛错；commit 用 `replace_suffix(cut_idx, summary+tail)` 单事务；提交后写 `outcome/tokens_before/tokens_after`。
- **验收**：三组注入测试——①切点落在一对 tool_call 中间；②提交瞬间取消；③提交后进程崩溃重启。三组都必须保持 tool_call 配对且不出现重复摘要。
- **不抄的部分**：OpenHands 的 React hook 实现不抄（绑定其事件总线），只抄它的状态机语义。

### 3.3 双时态软失效＋episode 溯源（#6+#3）
- **为什么必抄**：只要允许「流动」，旧摘要必然被新摘要取代；不保留 `valid_at/invalid_at` 就只能删行，一删就毁「可回溯」。graphiti 是这批里唯一把四个时间字段写进 schema 的（A 级）。
- **落地位置**：`nodes` 表加 `valid_at/invalid_at/expired_at/reference_time`；重摘要＝旧节点 `invalid_at=now,is_active=0`＋新节点 `valid_at=now,supersedes=old_id`；查询默认 `as_of=now`，审计查询可传 `as_of=过去`。
- **验收**：同一事实写两次后，`as_of` 旧时间返回旧摘要、`as_of` 新时间返回新摘要；两个版本都能下钻到原文 episode。
- **不抄的部分**：不引入图数据库（graphiti 依赖 Neo4j/FalkorDB/Kuzu/Neptune），只在 `node:sqlite` 里加列。

### 3.4 分总层「路由视图」：预计算窄画像＋预算二分＋每层成本（#17+#26+#16）
- **为什么必抄**：00 笔记与 01 构思的核心风险是「分总层变成更大的摘要」。supermemory 的 static/dynamic 双段画像（B 级）与 aider 的 repo map 预算二分（A 级）合起来给出另一种形态：**极窄、预计算、带预算控制的路由表**，而不是长摘要。
- **落地位置**：`router_view{tower_id,profile_static,profile_dynamic,time_range,activity,drill_cost,updated_at}` 常驻；生成器用 `budget_controller.build_view(tokens<=N)` 二分逼近预算；`drill_cost` 用历史 `flow_get` 平均 token 估算。
- **验收**：常驻前缀 token 稳定（塔增删之外不变）；单轮路由不调用 LLM；命中率/前缀稳定性可上报（见 #33 指标）。
- **不抄的部分**：supermemory 的「记忆抽取引擎」不抄（LLM 抽取事实、自动遗忘），v1 只做只读画像视图。

### 3.5 三步渐进检索工具面：search→timeline→get＋成本标注＋ID 引用（#16）
- **为什么必抄**：它是这批里唯一「按 token 定价的检索协议」：模型先看索引（便宜）、再看时间线（中）、最后取全文（贵），且每层都自报成本。claude-mem 的 README 直接给出量级（B 级）。
- **落地位置**：`tools/{flow_search,flow_timeline,flow_get}`；返回体固定带 `{ids[], token_cost, next_hint}`；prompt 里写「通常 2~4 次调用、够用就停」。
- **验收**：单问题工具调用次数中位数 ≤3；每次返回能自报 `token_cost`（用于校准 #33 指标）；模型不传 ID 时不允许直接返回正文。
- **不抄的部分**：其 Bun worker/Chroma 服务与跨 harness 汇总开关不抄。

## 4. 不该抄的清单

1. **不可恢复的有损压缩**：LLMLingua 式 token 删除（#39）、任何「摘要覆盖原文」后不留副本的实现。红线是「原文无损」，压缩只能发生在**视图层**，不能发生在**存储层**。
2. **把摘要当历史**：cline/OpenHands/claude-mem 全都保留 checkpoint 或事件流；只抄「摘要替换＋检查点」，不抄「摘要即历史」。
3. **AGPL 代码**：basic-memory（AGPL-3.0，#24）。Markdown 语法约定可以自己重写，**不要拷贝其源码/文档实现文本，也不要直接链接其库**；其 telemetry 默认开启，需显式关闭。
4. **许可证未明的代码**：serena、`modelcontextprotocol/servers` 的 GitHub API 返回 NOASSERTION（≠无许可证），商用前必须查仓库内 LICENSE 原文；servers 仓库自述「参考实现、非生产级」（#35）。
5. **已迁移/已停滞的主仓**：letta 主仓仅 1.4KB README 并指向 `letta-code`；graphrag 自述研究项目、维护模式、索引昂贵；GPTCache 2026-09 后停更；raptor 2024-09 后未更新。只能借机制，不能当依赖。
6. **需要重型外部服务的方案**：graphiti（图库＋LLM＋默认 telemetry）、claude-mem（Bun+uv+worker+Chroma）、OpenHands（Docker sandbox）、mem0/MemOS/hindsight/supermemory（server 或 cloud）、EverOS（Markdown+SQLite+LanceDB）、MemMachine（Neo4j+SQL）。DSH 桌面插件应保持「`node:sqlite` 单库＋本地文件」，最多加 FTS5。
7. **周期/在线全量重建**：EverOS cascade 全量索引、HTM M5 周期重建、graphrag 全量社区构建——在桌面端会撞 IO 与延迟。只抄**增量＋静默期批量**。
8. **语义缓存做记忆**：GPTCache 类（#30）。假阳性会把「相似但错」的旧答案当事实，且其召回指标与我们的「无损」目标不同源；最多做只读总述视图的缓存，key 必须含 `tower_id＋version`。
9. **摘要直接当系统指令**：awesome 收录的注入案例（#41）说明压缩摘要本身是不可信输入。摘要只能进「上下文数据区」，不能与系统指令同级。
10. **「分总层＝更大的摘要」**：Anthropic 的 context rot/attention budget（#31）与本项目 00 笔记《Harness the Memory》反证一致——宽召回会伤决策。分总层必须是路由器＋预算控制器，不是长总述。
11. **只按索引转述、不核实现的机制**：cline 的 Auto Compact/checkpoint 细节（本地 README 未核到，仅 `INDEX.csv` 第 17 行转述）、PageIndex File System（Cloud-only、本地无实现）、MemOS `tree_text_memory`（`INDEX.csv` 提及，本地 README 未写结构）。这些只能记为「待核线索」，不能写进设计依据。

**共同判据**：一个零件只要同时踩中下面任一条，就不进 v1——① 把原文改成不可寻址的形态；② 引入常驻进程/图库/云服务；③ 让摘要获得指令级权限；④ 结构变更无法回滚或无法实测结果。反过来说，能同时满足「原文可寻址、事务可回滚、摘要只导航、变更可观测」的零件才值得抄。
