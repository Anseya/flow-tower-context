# 06 实现核对清单（DSH 宿主契约）

> 基准：源码树 `...\integrations\dsh\deepseek-harness`（0.2.2-rc.3）＋安装版 asar。只读核对；行号均为核对时行号。
> 标记：【事实】= 源码/文档可直接引用；【待验证】= 推断或需装后实测。【建议】= 对 `plugin/flow-tower` 的改动建议。

## 0. 七条结论速览

1. `ctx.sessions.get(id)` 同步返回 `Session | undefined`；`snapshotEvents()/eventAt()` 可用但**已弃用（禁止新增调用）**。
2. `SessionEventRecord` 只有元数据；但 `sessionQuery.readSession/readEvent/readSurface` 返回**完整事件**，跨会话可还原 role/text，**不需降级**。
3. `ctx.on` 与 `tools.register` 本身就是 effect；`ctx.effect(() => () => store.close())` 是唯一必要的包装写法。
4. `tools.register` 返回 disposer；`exec.arguments`（非 args）、`exec.agent` 可选；返回值必须过 `output.schema`，`render` 返回 `ContentBlock[]`。
5. pre-step 载荷含 `agent`；`{...await next(), messages:[...]}` 是规范写法；自定义 `source:{kind,form:'snapshot',sections}` 合法，但注入消息会**永久累积**。
6. Host 平面 `systemPrompt.section()` 进 global 层 → 所有 agent 可见；缺 `inject` 时访问服务会抛错，而 inject 列了没人提供的服务会**静默 PENDING 永不激活**。
7. 本地安装 target **必须是绝对目录**；profile 记 `dependencies['x']='link:<path>'` + `dsh.profile.bundles`；desktop 有 HMR，新装免重启、**替换包需重启**；`list_plugins` 同样走 danger-full-access 升级，审批被禁会失败。

## 1. `ctx.sessions`（SessionStore）

- 【事实】`ctx.sessions` 即 `SessionStore extends Service`（`packages/core/session/src/index.ts:1058-1064`；`Context.sessions` 声明 `:40`）。
- 【事实】按 id 取 live session：`get(id: SessionId): Session | undefined`（`:1370-1377`）——**同步、找不到返回 undefined、不抛错**；另有 `list(): Session[]`（`:1379-1385`）。没有 `require/getOrThrow`；只有 detached/prepared 对象在 `liveEntryFor` 处才抛 "not live in this store"（`:1361-1368`）。
- 【事实】`snapshotEvents(fromSeq = 0, toSeqExclusive = this.seq): readonly SessionEvent[]`（`:718-737`，返回冻结数组，缓存整份快照）；`eventAt(seq)`（`:707-716`）。两者都带 `@deprecated`，注释明写 new calls are prohibited；`deriveEventMessage(event): Message | null`（`:1028-1030`）未弃用。
- 【事实】`session/event` 监听器载荷 `(session, event)`，scope-filtered、post-commit、监听器异常被日志吞掉（`index.ts:66-76`、`:900-904`）。
- 【事实】弃用依据与替代：`.agents/notes/implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.zh.md:15,25`（同步读取全弃用；按需历史改"显式异步分页、单次限定窗口"）。
- 【建议】监听事件后不需要回读；"按 seq 读原文"走 `ctx.sessionQuery`（见 2），不要**新增** `eventAt/snapshotEvents` 调用（现 `lib/raw.js:54` 属于新增）。

## 2. `sessionQuery.readSession/readEvent` 与跨会话原文

- 【事实】`SessionEventRecord = { sessionId, seq, type, time, surface }`（`packages/session-query/session-query/src/types.ts:61-72`）——**纯元数据，无法还原 role/text**；`listEvents()` 只返回它（`.../src/index.ts:264-272`）。
- 【事实】能还原的是另外三个：`readSession(sessionId): SessionLogSnapshot`（`types.ts:50-58`，`events: SessionEvent[]` 全量原始事件，含被 shadow 的；`src/index.ts:184-198`）；`readEvent({sessionId, seq, before?, after?}): SessionEventWindow`（`types.ts:135-161`，`src/index.ts:355-394`，返回 `target`+窗口 `events`+`startSeq/endSeq`；`before/after` 默认 0、上限 50：`src/index.ts:396-405`、`src/config.ts:6`）；`readSurface(sessionId)`（`types.ts:38-48`，只含当前 surface 节点，`src/index.ts:310-318`）。
- 【事实】三者在 live-preferred 逻辑语料上读：**未 live 的持久化会话也能读**；失败抛 `SessionQueryError`（坏 seq = `SESSION_QUERY_EVENT_NOT_FOUND`，`src/index.ts:372-378`）。
- 【事实】role/text 取法与 core 投影一致（`packages/core/session/src/surface.ts:120-152`）：`user/message` 的 `data` 本身就是 UserMessage（`data.content`/`data.source`）；`assistant/message`、`tool/result` 取 `data.message.content`；其余类型无消息。
- 【事实】desktop/web profile 必挂 `session-query-sqlite`（`packages/bundle/base/cordis.patch.yml:157-158`）。
- 【结论】跨会话可还原原文，**不需要"降级提示"**；现 `lib/tools.js:168-176` 的降级分支只是因为它只查 `ctx.sessions.get`。

## 3. `ctx.on` / `ctx.effect` 的 disposer 语义

- 【事实】`ctx.on(name, listener, opts?)` 返回 `() => boolean`，监听器归当前 fiber 所有、卸载自动移除（`docs/cordis-api/events.zh.md:127-149`）；`ctx.tools.register` 内部就是 `ctx.effect`，返回它的 disposer（`packages/core/tools/src/index.ts:128-153`，经 `packages/core/scope/src/store.ts:226-233`）。二者"已经是 effect"（`docs/cordis-tutorial/02-lifecycle-and-effects.zh.md:84-94`）。
- 【事实】`ctx.effect(execute, label?)`：execute 立即运行，其返回的清理函数被收集，卸载或调用返回的 disposer 时逆序执行，重复调用清理无副作用；支持生成器（yield 多个 disposer）（`docs/cordis-api/fiber.zh.md:10-35,336-340`）。
- 【事实】`ctx.effect(() => ctx.on(...))`：能跑但**多余**（`ctx.on` 已自带 fiber 清理）；直接 `ctx.on(...)` 即可。
- 【事实】`ctx.effect(() => tools.register(def))`：同样能跑但**多余**；多工具可用 `ctx.effect(function* () { yield ... })`（`packages/mcp/mcp-resources/src/tools.ts:31-63`）或逐个 register。
- 【事实】`ctx.effect(() => () => store.close())`：**正确且必要**（非 Cordis 管理资源的标准写法）。生产实例：`packages/workspace/workspace/src/index.ts:201`；`tianquan-app/index.js:189` 的 `ctx.effect(register)` 同形（register 返回 disposer）。
- 【事实】注册作用域取自"调用点 ctx"：cordis 4 的 service 访问返回 traceable 代理，`this.ctx` 解析为访问处 ctx（安装版 `@deepseek-ai/cordis/lib/index.js` 的 `createTraceable`）；`store.ts:226-233` 据此取 `scopeOf(ctx)`。
- 【建议】现 `index.js:70-77` 的 `effectOf()` 用 try/catch 吞掉一切异常；若 `ctx.effect` 抛 `INACTIVE_EFFECT`（fiber 已卸载）则注册与清理一起丢失且无日志。建议去掉 catch（让 apply 失败可见），或至少 `log.error`。

## 4. `ctx.tools.register(def)` 与 `execute(args, exec)`

- 【事实】`register(definition, options?): () => void`（`packages/core/tools/src/index.ts:121-153`）；**强制 `output:{schema,render,presentationMeta?}`**，缺失抛 TypeError（`:130-135`）；`output.schema` 须在受支持 JSON Schema 子集内（`:136`；`packages/core/tools/src/json-schema.ts:20-56,76-87`：type/oneOf/properties/required/additionalProperties/items/enum/const/description/title/default/examples；`type` 仅 object/array/string/number/integer/boolean/null）；`run_code` 保留名（`:145-147`）。
- 【事实】`exec` 的字段是 **`exec.arguments`（不是 `args`）**；完整：`callId/rootCallId?/name/schema?/arguments/agent?/toolSet?/parent?/signal/token`，外加 `deferContext()`/`concludeTurn()`（`packages/core/tools/src/contracts.ts:174-224,244-261`）；调用点 `tool.execute(exec.arguments, exec)`（`pipeline.ts:275`）。
- 【事实】`exec.agent` 是**可选**（`contracts.ts:186-187`）：程序化/agent-less 调用可能没有，模型直呼通常有 → 工具必须自己判空（`packages/todo/tool-todo/src/index.ts:195-199` 抛错；`packages/boot/plugin-manager/src/tools.ts:104` 判空）。
- 【事实】返回 value 必须是 lossless JSON 且**通过 `output.schema` 校验**（`pipeline.ts:537-541`；违反 → `ToolOutputError`/`INVALID_TOOL_OUTPUT`）；`render(args, value)` 返回 **`ContentBlock[]`**（`contracts.ts:16-23`；文本块 `{type:'text',text}`，`packages/llm/llm/src/types.ts:61-65`）；render 抛错也算 ToolOutputError（`pipeline.ts:542-547`）→ 必须 total。
- 【事实】`execute` 抛错 = 该次调用失败（isError 结果，模型看到错误文本），不是插件崩溃（`pipeline.ts:271-285`）。
- 【事实】纯 JS 不能 import `defineTool`；`defineTool` 的 `parameters` 是自定义简写并会转成 JSON Schema（`packages/core/tools/src/schema.ts:555-603`），而 `ToolSchema.parameters` 要求**本身就是 JSON Schema 对象**（`packages/llm/llm/src/types.ts:491-502`）→ 手写 JSON Schema 是正确做法（现 `lib/tools.js:83-96` 正确）。
- 【结论】现 3 个工具契约正确；补两点：`exec.agent` 判空的降级分支；`output.schema` 若含 `additionalProperties:false` 就不要返回额外字段。

## 5. `agent/pre-step` 载荷、`PreStepDecision`、消息 source

- 【事实】签名 `(payload, next)`；payload 声明为 `{agent, messages, turn, step, signal, modelSelection}`（`packages/core/agent/src/runtime-types.ts:350`；`agent` 由 fused dispatcher 注入，`packages/core/agent/src/dispatch.ts:113-118,143-147`）；`messages` 是已冻结的 `UserMessage[]`（`agent-loop/tests/interception.spec.ts:126-139`）。
- 【事实】`PreStepDecision = {kind:'reject'} | {kind:'enter', messages: UserMessage[], startsRequestSeries?: true}`（`runtime-types.ts:138-146`）；默认决策 = `{kind:'enter', messages: claimed + 当次 runtimeContext}`（`agent-loop/src/agent.ts:289-299`）。
- 【事实】waterfall 语义：调用 `next()` 继续链，不调用即否决（`docs/cordis-api/events.zh.md:99-125`）；规范写法 `const d = await next(); if (d.kind==='reject') return d; return {...d, messages:[...d.messages, extra]}`（生产实例 `packages/context/session-reference/src/index.ts:128-135`）。
- 【事实】`decision.messages` 在 step 的 firstAttempt 逐条 `session.append('user/message', message, {surfaceOp:'append'})`（`agent.ts:452-467`）；`source.kind==='runtime-context'` 的消息不逐字追加，而是被替换成当次组装的 runtime context（`:457-463`）。
- 【事实】UserMessage 必备字段 `{id, role:'user', content: ContentBlock[], source: MessageSource}`（`packages/llm/llm/src/message.ts:138-164`）；`MessageSourceMap` merge-extensible，producer 自 declare kind，消费方对未知 kind fall through（`message.ts:103-119`）。`source:{kind:'flow-tower', form:'snapshot', sections:[{name,text}]}` **合法**：`ContextFormed` 的 snapshot 分支要求 `sections`（`message.ts:86-101`），先例 `runtime-context`（`agent-loop/src/runtime-context.ts:13-17,157-168`）。
- 【事实】运行时**不校验** user/message 的 source kind：`validateSessionEventData` 只管 request-header/developer/tool 元数据（`packages/core/session/src/surface.ts:159-169`）；`canonical-envelopes.spec.ts:83-96` 只约束 system/message 必须 kind='system-prompt'；`user/message` 投影直接返回 `event.data`（`surface.ts:129-134`）。
- 【事实】副作用：非 `runtime-context` 的消息每步都会 append 成新 user/message，**从不被替换或去重** → digest 随压缩次数线性增长历史。
- 【待验证】工具续跑步（step>1、messages=[]）会把 user/message 追加在 tool/result 之后；结构上合法，但 DeepSeek adapter 是否接受需实测；稳做法是仅 `step===1` 注入。

## 6. `systemPrompt.section()` 的 scope 与 `inject`

- 【事实】`section(section): () => void` 在**调用点 ctx 的 scope** 注册并返回 Cordis effect disposer（`packages/core/system-prompt/src/index.ts:475-492`）；`PromptSection = {name, order, text: string | (ctx)=>string, interpolate?, complete?}`，order 必须有限（`:53-76,483-486`）。
- 【事实】全局层与 scope 链合并，同名时最近 scope 覆盖全局（`packages/core/scope/src/store.ts:192-217`）；Host 插件 `apply(ctx)` 的 ctx 无 scope tag（`scopeOf`→undefined：`scope/src/index.ts:154-156`；`store.ts:231`）→ 落 global 层 → **对所有 agent（含 subagent）可见**。测试佐证：root 注册为全局、scope 注册只影响本 scope 且可 shadow 同名（`packages/core/system-prompt/tests/scoped.spec.ts:32-64,66-79`）。
- 【事实】同层同名重复注册抛错（`store.ts:231-247`；错误信息 `system-prompt/src/index.ts:412-414`）→ section name 必须带插件前缀（现 `flow-tower:legend` 已满足）。
- 【事实】缺 `export const inject`：不等待服务，`ctx.<svc>` 在提供方未就绪时抛 "cannot get property … without inject"；`ctx.get(name)` 返回 undefined（`docs/cordis-tutorial/03-services.zh.md:82-90`；`docs/cordis-api/context.zh.md:239-243`）。
- 【事实】反向风险：**inject 列了无人提供的服务 → 插件永远停在 PENDING，无输出无报错**（`docs/cordis-tutorial/06-composition-and-hmr.zh.md:63`）。
- 【结论】`inject:['tools']` + `ctx.get('systemPrompt')`/`ctx.inject(['systemPrompt'], …)` 双路径是稳妥写法（现实现正确）；不要把 `sessions/sessionQuery/systemPrompt` 写进硬 inject。

## 7. bundle 安装（install_bundle / link / 重启 / 审批）

- 【事实】本地 target **必须是绝对目录**：`parseInstallSpec` 对相对路径抛 `a local path must be absolute`（`packages/boot/plugin-manager/src/install-spec.ts:60-77`）；模型侧 nextStep 也写 "an absolute local directory"（`src/tools.ts:17`）。**矛盾点**：`installBundle` 的 JSDoc 说包含 "local paths relative to the invocation directory"（`src/index.ts:830`），但不可解析的 spec 会被当作 registry spec 交给 pnpm，cwd=profile 目录（`src/index.ts:268-277`）→ 实际按绝对目录传。
- 【事实】本地 link 安装后 profile `package.json` 记录两处：`dependencies[<name>] = "link:<路径>"`（pnpm 可能写相对 profile 的路径或 `~/…`，`install-spec.ts:99-123`；测试模拟 `tests/package-reload.spec.ts:408-416`；官方源码安装也是 `link:${dir}`：`official-install-target.ts:57`）＋ `dsh.profile.bundles = [...names]`（`src/index.ts:1122-1142`）。
- 【事实】重启：desktop/web 的 base 层挂了 `hmr`（`packages/bundle/base/cordis.patch.yml:28-29`）→ 新装 bundle 可经 HMR 直接生效（`change()` 初始 application='applied'，`src/index.ts:1212-1226`）；**替换已安装包需重启**才能加载新的 JS module 代（技能文档 `...\dsh-doc\references\host-plugin.md:75`；restartReason 枚举 `src/types.ts:46-52,158-160`）。
- 【事实】`list_plugins` 不是只读旁路：`plugin_manager` 每个 action 先 `approveEscalation({requestedMode:'danger-full-access', effectiveMode: policy.resolve(...)})`（`src/tools.ts:87,103-110`）。effective mode 已是 danger-full-access 则直接放行；否则必须有审批通道，无审批服务/无 agent/被拒/不可用均抛错（`packages/sandbox/sandbox/src/escalation.ts:172-205`）。base 默认把会话钉在 `workspace-write`+`ask`（`base/cordis.patch.yml:237-262`）→ **审批被禁用的常规会话里 list_plugins/install_bundle 会直接失败**（除非会话 mode 已是 danger-full-access）。
- 【待验证】pnpm 写回 `link:` 的字面形态（相对 vs `~/` 展开）随 profile 位置而变，以装后实际 `package.json` 为准。

## 8. 对 `plugin/flow-tower` 最需要改的三处

1. **`dict_cite` 改用 sessionQuery**：现 `lib/tools.js:52-63` 只查 `ctx.sessions.get`，非 live 会话只能降级（`:168-176`）。改用 `ctx.get('sessionQuery').readEvent({sessionId, seq, before, after})`（或 `readSession`）即可在重启后逐字 replay，删掉降级分支。
2. **原始 seq 回放不要用 `session.eventAt()`**：`lib/raw.js:54` 是被明令禁止新增的同步读取（Agent Note:15）；改为 sessionQuery 异步读＋自写映射（`user/message→data`、`assistant|tool→data.message`，等价 `surface.ts:129-146`）。
3. **digest 不应无限累积**：除 `runtime-context` 外 pre-step 消息不会被替换（`agent.ts:457-465`）。优先改成 `systemPrompt.context()` 快照（RuntimeContextProjection 会自动替换、不增长历史，`runtime-context.ts:118-168`）；若保留消息注入，则限 `step===1` 并维持 version 去重＋设注入次数上限。
